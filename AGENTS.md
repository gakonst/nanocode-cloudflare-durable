# Development and deployment

This is a separate Cloudflare app. Its sibling `../nanocodex` supplies the Rust SDK. `sdk-revision.json` records the SDK branch and revision containing the required activity and pending-operation APIs; check out that revision in the sibling when preparing a fresh workspace. Keep SDK changes in that workspace and Worker-specific code here. Do not add code comments, README files, Cargo features, wasm-bindgen glue, tests, or test-only dependencies.

The WASM agent and SQLite checkpoints run inside the same session Durable Object. A stable session UUID is persisted before SDK initialization. Requests are queued durably and deduplicated by `request_id`; reusing an ID with different input returns 409. SDK ownership fences, revision checks, immutable records, model receipts, tool receipts, subagent journals, and checkpoints use the persistent store. No memory store is used for agent state.

Alarms drive work independently of client connections. A watchdog alarm is persisted before execution, using `RECOVERY_DELAY_MS` as an operator recovery policy. Completed requests return saved results. Interrupted model calls may repeat; dispatched tools retain the SDK's uncertain-outcome handling. The Worker does not promise exactly-once model billing or external side effects. Concurrent sessions use independent Durable Objects. Each session executes queued root turns serially, while SDK subagents can run concurrently. Durable background markers keep alarms armed after root requests finish until the SDK task tree, continuation turns, and journal writes are quiescent. Resume pending SDK operations in accepted order before later requests. Cancellation must settle in the SDK before the queue reports it complete. The `subagent-completion:` request-ID prefix is reserved.

Use two deployments. The public `nanocode-worker` owns session Durable Objects and Connect ingress. The private `nanocode-egress` owns the account authority, credential vault, provider transports, connector transports, and authentication for execution hosts. The public deployment must have no provider credentials, vault key, account namespace binding, or credential-returning interface. Named entrypoints share the private deployment. The agent's only outbound network capability is a trusted host adapter to those bindings; agent-selected account IDs, headers, and URLs do not confer authority.

`AccountAuthority` owns rotating subscription credentials, Connect grants and token families, selected connections, app/origin/principal bindings, and thread routing. It serializes refreshes, commits an uncertain-exchange marker before contacting the token endpoint, and persists rotated credentials before releasing access material inside private egress. An uncertain refresh requires importing a fresh credential document. Credentials stay in Cloudflare secrets and encrypted Durable Object storage. A Container is not required for authentication or inference. Worker secrets and access tokens must never appear in source, command arguments, logs, or benchmark reports. The retired `SubscriptionAuth` class remains exported to retain its namespace without deleting existing storage; it no longer serves credentials.

Cloudflare chooses physical Durable Object placement. Agent execution and checkpoint storage are co-located by construction; this does not pin all objects or the account authority to an exact Cloudflare colo. SQLite access stays inside each session, including the full SDK subagent tree. Reuse the resident WASM instance and SDK session across turns; status and event history must not initialize WASM. Root turns are serial, while SDK children can run concurrently. Connect grants use separate SDK session identities inside the same thread DO. Fresh grants must not inherit previous grant transcripts or outputs.

The default tool collection omits local machine tools and enables SDK delegation. Shell, filesystem, desktop, and remote Code Mode execution require a separately configured execution host; this app does not create a machine environment. Use the SDK RemoteFrame/RemoteOperation protocol for that host, with orchestration and tool receipts remaining in the brain. A machine executor's unrestricted network access is governed by that host; the Worker cannot enforce a proxy for an independently configured machine.

Every external Connect operation has a live account authorization check. Connector calls check canonical authority even when an access credential is cached. Revocation also writes durable session fences and retries delivery through an account outbox. Acknowledgment means the fence is durable, and already-dispatched external effects cannot be recalled. Generic vault operations return only status; arbitrary response-body redaction is not a credential boundary. Cache lifetimes, token lifetimes, recovery delay, event page size, stream revalidation, and execution-host frame and timeout policies are explicit Wrangler variables.

Install Rust 1.97 or newer, the `wasm32-unknown-unknown` target, and Node.js. Run `npm ci`, `cargo check --locked --lib --target wasm32-unknown-unknown`, `npm run check`, and `npm run dry-run`. Run SDK checks from `../nanocodex` with `cargo check --locked --lib` and `cargo check --locked --lib --target wasm32-unknown-unknown`. Local compilation keeps incremental artifacts without debug information. The optimized WASM build uses the `wasm` profile. Dependency resolution is pinned by both lockfiles.

Deploy from this directory:

For interactive login, use the existing Brave Browser profile through the installed CUA provider recorded in `~/.nanocodex/runtimes/openai-cua/provider.json`. That provider owns the working native application connection. A fresh Chrome profile does not share the user's saved login or browser session. Unlock 1Password through its normal UI when the saved credential requires it.

1. Run `npx wrangler login`, or provide `CLOUDFLARE_API_TOKEN` through your secret manager.
2. Run `npm run dry-run` to review both deployment bundles, then `npm run deploy` when deployment is authorized.
3. Set the public API access token with `npx wrangler secret put WORKER_TOKEN --config wrangler.jsonc`.
4. Run `node scripts/import-oauth.mjs /absolute/path/to/oauth.json`. Omitting the path reads the default Claude Code credential from the macOS keychain. The importer accepts Anthropic entries from Pi/OMP-style documents and Claude Code's `claudeAiOauth` document, and pipes only the normalized Claude credential into `wrangler secret put OAUTH_JSON`. It does not write a credential file.

For API-key authentication instead, set `ANTHROPIC_API_KEY` with `wrangler secret put --config wrangler.egress.jsonc` and omit `OAUTH_JSON`; set public `MODEL_AUTH` to `api_key`. Subscription authentication takes precedence when both are configured. Do not run the same rotating refresh credential independently in multiple deployments or local clients; use a dedicated login when independent refresh ownership is needed. Uploading a fresh credential document changes the seed digest and resets the account's retained credential state. `ANTHROPIC_ENDPOINT` belongs only to private egress and is an operator-approved upstream transport override.

Owner API requests require `Authorization: Bearer $WORKER_TOKEN`. Submit `POST /sessions/<name>/turns` with JSON `{"request_id":"job-1","prompt":"Your instruction"}`; the response is 202 while queued or running. Poll `GET /sessions/<name>/turns/job-1` for the final result. Repeating the POST with the same input returns the saved result after completion. Cancel with `POST /sessions/<name>/turns/job-1/cancel`. Read bounded event pages at `GET /sessions/<name>/events?after=0&limit=128` and process counters at `GET /sessions/<name>/metrics`. `GET /health` reports the configured model and authentication mode. Subscription requests retain the SDK's pinned wire compatibility. Run `npm run dev` for both deployments in one local workerd session.

Runtime measurements:

- `npm run dry-run && node scripts/measure-local.mjs` runs the compiled WASM in local workerd against a deterministic mock streaming provider, measures initial and restored turns and receipt replay, then restarts workerd during inference and verifies recovery. The idle-session measurement uses Durable Object eviction; the in-flight measurement forces runtime replacement because ordinary eviction waits for active references.
- `node scripts/measure-local.mjs --live` requires `OAUTH_FILE` containing a dedicated subscription login or `ANTHROPIC_API_KEY` in the environment. It measures short Opus 5.5 requests, including session restoration after eviction. Reports contain only the fixed measurement prompt's response and safe counters.
- `node scripts/measure-authority.mjs` measures coalesced rotating refreshes, zero-authority-RPC warm model dispatch, encrypted rotation, and fail-closed recovery after runtime replacement during refresh.
- `node scripts/measure-capabilities.mjs` invokes the actual WASM SDK catalog, connector and vault tools, verifies credential injection and safe projections, and checks model input and persisted receipts for credential exposure.
- `node scripts/measure-connect.mjs` exercises PKCE, origin and grant isolation, hosted turns and durable events, service-only connector/vault calls, refresh reuse and revocation.
- `node scripts/measure-remote.mjs` builds the SDK runner and exercises the actual remote Code Mode protocol against a separate native execution host, including workspace edits, Bash, persisted code cells, callbacks and uncertain disconnects. Its loopback transport measurement is not a production networking benchmark.
- `node scripts/measure-wrangler.mjs` runs both deployments through Wrangler, verifies TypeScript hot reload without rewriting WASM, and replaces Wrangler during inference to check autonomous disk-backed recovery. It temporarily edits and restores a health response field; run it while the Worker source is idle.
- `node scripts/benchmark-transfer.mjs 65536 256` compares JSON byte-array round trips with the raw memory copy used by the WASM HTTP body bridge for 16 MiB of data. This isolates serialization cost, not inference throughput or full application speed. Chunk size and count are benchmark inputs.

Keep all reports and generated bundles in ignored `output/`, `dist/`, and `target/`. Local workerd latency does not establish production colo latency. First-time optimized builds, cached builds, mock-provider overhead, and live model latency are separate measurements.
