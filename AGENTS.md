# Development and deployment

This repository is the nanocode Cloudflare Worker: nanocode agents running in Durable Objects, as a library and a default deployment. Its sibling `../nanocode-wasm` (gakonst/nanocode-wasm) supplies the agent runtime, the Rust SDK compiled into one WebAssembly module with its host-agnostic TypeScript host, as the npm dependency `file:../nanocode-wasm`. `wasm-revision.json` records the package revision the Worker builds against, and the package's own `sdk-revision.json` records the SDK master revision it builds against from `../nanocodex`; check out both revisions in the siblings when preparing a fresh workspace. Keep SDK changes in the SDK, host-agnostic WASM bridge changes in the package and Cloudflare-specific code here. Hosted platform pieces (private egress with credential storage, the vault, execution-host fleets, identity and connectors) live in gakonst/nanocode-platform, which consumes this library. Do not add code comments, README files, Cargo features, wasm-bindgen glue, tests, or test-only dependencies.

`src/index.ts` exports `createNanocode(options)`, which returns the `AgentSession` Durable Object class and the Worker `fetch` handler. The library defines interfaces and ships no adapters. `options.authenticate(request, env)` returns the caller's account ID, `{account, read_only: true}` for a caller that may only read, or `null`; each account's sessions live in separate objects named by `[account, session]`. A read-only caller gets 403 for every session request other than GET and for attaching a hand, and its session socket streams events but answers `turn` and `cancel` with 403 and `warm` with `warmed: false`. A principal may also carry `grant`, a JSON value the host defines, and `expires_at`, its credential's expiry in milliseconds since the epoch. The session keeps both with each turn the caller submits, with its session socket's registration and with its hand's `hand_sockets` row, and passes the grant of the turn it is running to host tool calls. Sockets and event streams outlive the request that authenticated them, so the session checks the caller before it admits each session socket message, before it delivers events to a watcher, before each read of an event stream and before each frame it sends to a hand or accepts from one, in arrival order: past `expires_at`, or when the optional `options.active(account, grant, env)` returns false or throws, it sends the session socket `{"type":"error","error":"access token expired or revoked"}` and closes it with 1008, ends the event stream, or disposes the hand connection, which fails the cell that was being sent with an unknown outcome and detaches the hand. Event delivery runs the `active` check in the background, so a watcher can receive the batch published while its first failing check runs; hosts that cache the answer bound how long a revocation takes beyond that. The error frame arrives at once, but a close issued outside the socket's own message handler reached the client about 10 s later in local workerd and 42 s later in production, while one issued from its message handler arrived within 319 ms in production. `options.egress(env)` returns anything with `fetch(request)` that answers the egress contract: `POST /model` with the provider body and the `x-nanocode-model` JSON header `{provider, authority, endpoint, headers, subscription}`, `GET /socket` upgrades for Codex Responses sockets with `x-nanocode-socket`, `GET /remote` upgrades to a configured execution host with `x-nanocode-authority`, and `GET /metrics`. A service binding to a separate Worker satisfies it directly. `MODEL_AUTH` tells the agent whether both providers use subscription or API-key wire compatibility; the optional `options.subscription(account, env, provider)` decides it per account and provider instead, for an egress that holds each account's own credentials. The optional `options.recordSession(account, name, env)` lets a host keep an index of each account's sessions: a session object calls it before handling its first request and, once it returns true, writes a `recorded` metadata row and never calls it again, so sessions created earlier are indexed on their next request; false means the account no longer exists, and the session deletes its storage and answers 403. The returned `deleteSession(account, name, env)` calls the session object's internal delete route, which the public routes cannot reach: it closes the session's hand and watcher sockets, disposes its runtimes and their model sockets, deletes its alarm and all of its storage, and the instance answers 410 until it is evicted. Claude subscription sessions use Claude Code's wire compatibility. Codex subscription sessions use the ChatGPT Responses WebSocket with `OpenAiAuth::host_managed_chatgpt()`, and Codex API-key sessions use the public Responses API at `https://api.openai.com/v1` over HTTPS with `OpenAiAuth::gateway_managed()` and the SDK's default of store: false, so every model call replays the full history and OpenAI retains nothing; Codex subscription sessions also keep store: false, as the ChatGPT backend requires, and continue responses on their socket. The SDK can store and continue API-key responses with `.store(true)`, but measured through AI Gateway storing a response delayed its first byte by about 0.2 s while continuing one saved only request bytes, so the Worker leaves it off. The egress must agree, and a resident runtime reopens when a later turn's mode differs. The library makes no outbound requests itself and holds no credentials.

The default deployment in `worker/` uses Cloudflare AI Gateway through the `AI` binding. `worker/gateway.ts` implements the egress contract with `env.AI.gateway(AI_GATEWAY_ID).run()`: Claude Messages requests go to the gateway's Anthropic provider with only the `accept`, `content-type`, `anthropic-version` and `anthropic-beta` headers, Codex Responses requests go to its OpenAI provider's `responses` endpoint with only `accept` and `content-type`, the gateway supplies the provider key from BYOK or bills through Unified Billing, and the response streams back with provider and `cf-aig-*` headers. Binding requests are pre-authenticated, so the Worker holds no provider key or gateway token. The route parses each body anyway to pass it as the binding's `query`, so it answers with an `x-nanocode-model-diagnostic` of the request's body bytes, input item count and whether it continued a previous response, which session metrics list in `model_diagnostics`. The gateway route carries both providers over HTTPS only: `/socket` answers 426, so Codex keeps to HTTPS, and Codex subscriptions and execution hosts need an egress that serves them, such as the platform's; `/remote` answers 501, so a turn naming an executor fails at once with that answer as its error. `worker/index.ts` authenticates one account by comparing the bearer token's SHA-256 with the `ACCESS_TOKEN_SHA256` variable; an empty value rejects every request. Against an account's `default` gateway with no key in the Worker, a deployed Claude turn completed through the binding in 3.4 s of run time. On 2026-10-19 the deployed default Worker completed a Codex turn through the gateway's OpenAI provider in 6.8 s from submission on a new session and 2.1 s on the next turn, and a Claude turn in 5.0 s. A deployed Codex turn of three sequential `list_agents` calls and a reply sends 36.8–43.1 KB on every call, 158 KB and 169 KB per turn; with store: true (SDK b651367, since reverted) it sent 2.1 KB on each continued call, but the median model-call time rose from 1.56 s to 2.15 s. A Claude turn through the same route completed in 4.6 s.

The WASM agent and SQLite checkpoints run inside the same session Durable Object. A stable session UUID is persisted before SDK initialization. Turns are queued durably in the SDK's turn inbox and deduplicated by `request_id`; reusing an ID with different input returns 409. SDK ownership fences, revision checks, immutable records, model receipts, tool receipts, subagent journals, and checkpoints use the persistent store. No memory store is used for agent state.

Alarms drive work independently of client connections. A watchdog alarm is persisted before execution, using `RECOVERY_DELAY_MS` as an operator recovery policy. Completed requests return saved results. Interrupted model calls may repeat; dispatched tools retain the SDK's uncertain-outcome handling. The Worker does not promise exactly-once model billing or external side effects. Concurrent sessions use independent Durable Objects. Each session executes queued root turns serially, while SDK subagents can run concurrently. Durable background markers keep alarms armed after root requests finish until the SDK task tree, continuation turns, journal writes, and detached remote execution are quiescent. Resume pending SDK operations in accepted order before later requests. Cancellation must settle in the SDK before the queue reports it complete, except for a turn whose runtime cannot open, which finishes cancelled at once and which the SDK cancels on admission when the runtime next opens. The SDK reserves the `subagent-completion:` request-ID prefix for its own continuation turns, and admission answers 400 for it.

A turn waits instead of running while its execution host is unavailable: when the runtime for it cannot open, or it names a `hand` that is not attached, the pump classifies the failure from its signal and does not guess. Permanent failures finish the turn as failed with `error` and `kind` in its result, so a client's wait ends: a non-101 answer from egress `/remote` with a 4xx status other than 408 and 429, which is `unauthorized` for 401 and 403 and `rejected` otherwise, a 501 (`rejected`), and a runtime configuration the SDK refuses while building it (`configuration`, which `init` answers as a rejection). Everything else is transient and keeps the turn queued, or running for a recovered turn, under `RECOVERY_DELAY_MS`: a 5xx other than 501, 408 or 429 from `/remote` (`unavailable`), no HTTP answer, the `REMOTE_TIMEOUT_MS` connection deadline or a socket closed before its catalog (`unreachable`), an absent hand (`detached`) and any other open failure (`runtime`). The SDK session log's `retry` keeps the message, kind, attempt count and next retry time on the turn, its status report shows them as `error`, `kind`, `attempts` and `retry_at`, and its event stream gets a `retrying` event when the error first appears or changes, not on every retry. A hand attaching starts a turn waiting for it at once. Cancelling a waiting turn finishes it, and session metrics report the pending alarm as `alarm_at`, `null` once nothing is left to retry. The pump commits the background marker only once a queued turn's runtime has opened, so a turn whose runtime never opened leaves nothing retrying after it fails or is cancelled; with no unfinished turn, a permanent failure drops an existing marker and a transient one keeps retrying for the SDK's background work.

Cloudflare chooses physical Durable Object placement. Agent execution and checkpoint storage are co-located by construction; this does not pin all objects to an exact Cloudflare colo. SQLite access stays inside each session, including the full SDK subagent tree. Reuse the resident WASM instance and SDK session across turns. Status, a queued turn's cancellation and event history read through the SDK's session log on a WASM instance without opening the SDK session (instantiating the compiled module took 0.3 ms locally), and opening the session later reuses that instance. Root turns are serial, while SDK children can run concurrently.

The default tool collection omits local machine tools and enables SDK delegation. Shell, filesystem, desktop, and remote Code Mode execution require a separately configured execution host; this Worker does not create a machine environment: hands dial in, and an egress may connect configured execution hosts at `/remote`. Use the SDK RemoteFrame/RemoteOperation protocol for that host, with orchestration and tool receipts remaining in the brain. A machine executor's unrestricted network access is governed by that host; the Worker cannot enforce a proxy for an independently configured machine.

Recovery delay, event page size, event coalescing, the event-stream keepalive interval (`EVENT_STREAM_KEEPALIVE_MS`), the model-socket linger, the runtime memory budget, and execution-host frame and timeout policies are explicit Wrangler variables.

Install Rust 1.97 or newer, the `wasm32-unknown-unknown` target, and Node.js. Run `npm ci`, `npm run check`, and `npm run dry-run`. The Worker has no Rust of its own: `npm run build` runs the package's fingerprinted WASM build (`npm --prefix ../nanocode-wasm run build`), and the bundle imports the module as `nanocode-wasm/nanocode_wasm.wasm`. Run the package's checks from `../nanocode-wasm` and SDK checks from `../nanocodex` with `cargo check --locked --lib` and `cargo check --locked --lib --target wasm32-unknown-unknown`. `package-lock.json` pins the Worker's npm dependencies and the package's lockfiles pin the WASM build.

The package's `AgentRuntime`, `EventHub` and `RemoteExecutor`, its bridge ABI and command table are documented in `../nanocode-wasm/AGENTS.md`; protocol, turn and event logic belongs in the SDK and host-agnostic glue in the package. The session Durable Object supplies the package's host interfaces. `src/store.ts` is its `SqlHost`: it runs each `store` or `log` operation's statements in one `transactionSync` and answers with each statement's rows; metrics count the two separately (`checkpoints` and `log`). The SDK owns the `states`, `owners`, `records`, `turns` and `events` tables, their fencing, revisions and record immutability, turn states and event sequence; the Worker only reads their row counts for metrics. Model requests go to egress `/model`; Codex Responses sockets upgrade through egress `/socket`, and the session accepts the WebSocket and hands it to the package with the egress's `x-nanocode-stream-idle-ms` deadline. `src/remote.ts` dials a configured execution host through egress `/remote` with `RemoteExecutor.connect` and throws `ExecutorRejection` with the status of a refused upgrade, and hands attach through the hibernation API with `RemoteExecutor.accept` and `restore`, so frames stay opaque, `REMOTE_MAX_FRAME_BYTES` is enforced and each hand's catalog text is kept for hibernation. The package flags each batch that holds a request the SDK's `RemoteFrame::dispatches` marks as starting work, so the session refuses that batch once the turn's cancellation is requested without decoding frames. Two commands run on the scope's WASM instance without opening the SDK session: `catalog` reads the name a hand advertises in its catalog, and `admit` asks the SDK's `admit_prompt` whether a turn may enter the inbox, so admission takes the reserved request-ID prefix and the provider rule from the SDK. Each logged event batch reaches the session's `published` callback with `host_timing`, the session answers a finished turn's timings through `finishing`, and the SDK selects each turn's hand with `select_prompt_hand`; turn states, the queue, cancellation before and during a turn, resumption in accepted order, event attribution and quiescence live in the SDK. Egress injects provider credentials, so Claude clients send no auth headers and Codex uses `OpenAiAuth::host_managed_chatgpt()`.

Hosts add their own tools through `createNanocode({ tools: { definitions, call } })`. Each definition's `name`, `description` and JSON Schema `parameters` reach the runtime when it opens, and the package registers them as the SDK's `FunctionTool`s beside the SDK's own tools, offered directly or inside Code Mode scripts. A call crosses the bridge as the `tool_call` host operation; the session Durable Object takes the durability wait it takes before any external effect, refuses it once the turn's cancellation is requested, and awaits `call({ authority, name, input, grant }, env, signal)`, whose result becomes the tool output and whose thrown error a tool error. `grant` is the grant of the turn the session is running, read from its `background:<scope>` row, which holds that turn's descriptor until the runtime settles, so subagents and other background work that continue after a turn run with the grant of the latest turn the session started, and turns submitted before grants existed carry none. The SDK keeps the call's receipt like any tool's, so an interrupted call reports an unknown outcome instead of running again, and session metrics count `host_tool_calls`. Whatever the host keeps out of the result never enters WASM memory, checkpoints or events; the platform serves its credential tools this way so injected secrets stay in its egress.

Deploy from this directory:

1. Run `npx wrangler login`, or provide `CLOUDFLARE_API_TOKEN` through your secret manager.
2. In AI Gateway, use the `default` gateway or create one and set `AI_GATEWAY_ID`. Add an Anthropic key under Provider Keys with the `default` alias, or load Unified Billing credits; the AI binding consults only the `default` alias.
3. Generate an access token, keep it in your secret manager, and deploy with its digest: `npx wrangler deploy --var ACCESS_TOKEN_SHA256:$(printf %s "$TOKEN" | shasum -a 256 | cut -d' ' -f1)`. Clients and hands send the token itself as `Authorization: Bearer`.
4. `npm run dry-run` builds the WASM and bundles the Worker into `output/deploy` for review.

Requests require `Authorization: Bearer <access token>`. Submit `POST /sessions/<name>/turns` with JSON `{"request_id":"job-1","prompt":"Your instruction","provider":"claude"}`; the response is 202 while queued or running. Poll `GET /sessions/<name>/turns/job-1` for the final result; while the turn waits on an unavailable execution host the report adds `error`, `kind`, `attempts` and `retry_at`. Repeating the POST with the same input returns the saved result after completion. Cancel with `POST /sessions/<name>/turns/job-1/cancel`. Read bounded event pages at `GET /sessions/<name>/events?after=0&limit=128` and process counters at `GET /sessions/<name>/metrics`. `GET /sessions/<name>/socket?after=<seq>` upgrades to a hibernating session WebSocket that first sends every stored event after the cursor and then each new one as `{"type":"event","seq","request_id","created_at","event"}`. On it the client sends `{"type":"turn",...}` with the turn body and `{"type":"cancel","request_id"}`, answered by `{"type":"turn"|"cancel","request_id","status","body"}` with the HTTP route's status and body, and `{"type":"warm"}`, answered by `{"type":"warm","warmed"}`. The text message `ping` is answered `pong` by the runtime without waking the session. Reconnect with the last `seq` seen as `after`. `scripts/worker-client.mjs` uses this socket and sends `warm` on the first keypress of each interactive prompt. Omit `provider` for Claude Opus 5.5; `"provider":"codex"` selects GPT-6.1 Sol when the egress serves Codex. Provider selection is durable and immutable within each SDK session: the session records its first turn's provider and the SDK's `admit_prompt` refuses another with 409; choose a new session name to switch providers. The first turn's `executor` binds the session the same way, a rule the Worker keeps itself because the SDK records no executor. `GET /health` reports supported models and the Claude authentication mode; it does not probe provider availability. Subscription requests retain the SDK's pinned wire compatibility. `npm run dev` runs the Worker under Wrangler with the remote AI binding.

Keep all reports and generated bundles in ignored `output/`, `dist/`, and `target/`. Local workerd latency does not establish production colo latency. First-time optimized builds, cached builds, mock-provider overhead, and live model latency are separate measurements.

Turn admission submits the turn to the SDK's session log, then commits the stable UUID and watchdog before starting the resident pump through `waitUntil`. The pump reads the oldest unfinished turn, opens or reuses the runtime for its descriptor, commits the background marker before it drives a queued turn, asks the inbox to drive one turn and to settle, and schedules alarms; a turn whose cancellation was requested blocks the session's effects until the drive returns. Alarms remain the independent recovery driver. The normal path reuses the already committed watchdog; recovery recommits an existing marker, or one for a running turn, before SDK initialization. Committing the marker in the pump with the descriptor it compares against, instead of at admission with differently ordered keys that the pump then rewrote, saved one statement and one row written per turn: in two alternating `measure-store.mjs` runs on 2026-10-19 against the bundle built before, the object wrote 29.4 instead of 30.4 rows per Claude turn and 80 instead of 81 per Codex turn, with workerd CPU per turn of 12.0 against 11.8 ms and 22.0–23.0 against 21.0–23.0 ms. `Accept: text/event-stream` on the owner turn POST returns a finite, request-scoped durable stream through its terminal result. Disconnecting that stream does not cancel execution. The existing GET event stream includes the full SDK tree. An `after` cursor beyond a saved terminal event returns an empty finite stream. The session keeps its `metadata` rows in memory (`Metadata` in `src/store.ts`): it is their only writer, every write goes through that copy and a failed `transactionSync` drops it, so admission, the pump, host tool grants and `warm` read the bound authority, provider, executor, session ID and background marker without a statement and skip inserting rows that already exist. The pump also keeps the pending list it read, so after a turn that was the only unfinished one, with no admission since, it stops instead of running a second iteration that scanned the turns again, read the marker twice and rearmed the alarm. In three alternating `measure-store.mjs` runs of 60 Claude and 15 Codex turns on 2026-10-20 against the bundle built before, statements per turn fell from 57 to 42 and from 120.5 to 105.5, rows read from 169 to 111 and from 274 to 238, alarm writes from 3 to 2 and session log calls from 8.8 to 7.8 and from 20.7 to 19.7, rows written stayed 29.4 and 80, and workerd CPU per turn was 12.5 against 12.8 ms and 21.3 against 22.7 ms. A partial index on unfinished turns (`ON turns (scope, first_seq) WHERE status IN ('queued', 'running')`) measured the same way added 2 rows written per turn, to 31.4 and 82, and saved 33 and 9 rows read, so the pending scan stays an unindexed scan of the scope's turns: at a thousand reads per written row it pays off only past about 2,000 turns in one session.

Hot-path writes do not wait for storage confirmation one at a time. Model dispatch, model socket frames, and executor and hand frames each await `storage.sync()` first, so every earlier write, including SDK receipts, checkpoints and the admitted job, is durable before that effect leaves the session. A tool call one hand's script forwards to another hand, and its result returning to that script, skip the wait: they carry only the hands' own input and output, and the brain keeps no receipt for them. Responses and streamed events are held by Durable Object output gates until earlier writes are confirmed. A turn therefore pays one confirmation wait before its first model request instead of one per write, and a crash before confirmation loses only work that nothing outside the session has observed. In production that single wait averaged 42 ms for Claude and 52 ms for Codex turns, replacing an admission sync, a running-state sync and a sync per checkpoint and event batch before the first dispatch.

Durable Objects bill wall-clock time while an object is handling work or holding a non-hibernatable WebSocket, and SQLite bills every written row including each index entry. Keep both off idle sessions and out of the per-event path. An event-stream response keeps the session object active and billed for as long as it is open, because the object writes to it. The session socket is accepted through the hibernation API, so an idle connected client costs nothing and the object is evicted as if none were attached; prefer it for clients that stay connected. Each watcher's authority is a row in `watch_sockets` and its cursor is in the socket attachment, so events reach watchers after the object is restored. Events are one row each in the SDK's `events` table with `seq` as the plain integer primary key: no secondary index and no `AUTOINCREMENT` counter, and sessions created before that keep their table but drop its indexes. A turn's stream reads its own `first_seq`..`last_seq` range from the SDK's `turns` table, so per-turn reads scan only that primary key range. The SDK hands each logged batch to the session, which pushes it to every socket watcher whose cursor it continues and serves event streams from a tail of up to `EVENT_PAGE_SIZE` recent contiguous events; a watcher or stream further behind pages through the SDK log. Sessions created before the SDK inbox kept their turns in `jobs` and Codex turn mappings in `event_turns`; the first construction after the upgrade imports every job into the SDK's `turns` table inside `blockConcurrencyWhile`, unfinished ones with their prompt and finished ones pointing at their stored result event, and drops both tables, so history, idempotent resubmission and pending work continue. Codex raw provider frames (`api.event`) are not emitted, as in the native CLI; they were most event rows and bytes. The SDK's `SessionEvents` pump sends the first event after a quiet period at once and then at most one batch per `EVENT_COALESCE_MS`, an operator policy for how often a streaming client sees new text (100 ms, ten updates a second), and merges consecutive assistant and reasoning-summary deltas of the same item into one event. A turn that waits for its events to drain flushes immediately, so coalescing never delays a result. Model request bodies and Codex socket frames cross from WASM as raw bytes through the `dispatch_body` import, and the session forwards a model body to egress unchanged with its routing in the `x-nanocode-model` header, so a large request is not JSON-escaped and parsed again on the way out. Event coalescing then halved rows written per turn in a local 20-turn run with 40 text deltas per reply, from 81.6 to 42.9, and cut bridge event calls from 945 to 89. A CPU profile of a 110-turn local session with 200 deltas per reply (`INSPECT=<port>` in a profiling harness with an unstripped build) found software SHA-256 in 38% of samples; with the SDK's BLAKE3 record keys WASM CPU per turn fell from 173.5 ms to 20.7 ms and storage from 19.1 MB to 12.1 MB. Session metrics report `database_bytes`, the object ID for analytics, and the resident runtime's `wasm_memory_bytes`. The package's `wasm` profile, measured on the same 110-turn run, and the module's size are documented in `../nanocode-wasm/AGENTS.md`.

The WASM module is the package's: `node scripts/measure-size.mjs` in `../nanocode-wasm` measures its size by crate and function, and its `AGENTS.md` records what the module contains.

Hands are machines that dial a session so its scripts can use them, such as the laptop where a prompt was typed. A hand is the whole machine under a name, not a workspace: `nanocode hand wss://<host>/sessions/<name>/hands` with the access token in `NANOCODE_RUNNER_TOKEN` attaches the calling machine under its host name, and `--name` or a final `/hands/<name>` path segment names it otherwise. Every session accepts hands. The socket terminates in the session Durable Object through the WebSocket Hibernation API, so an idle attached hand does not keep the object in memory or billed: each hand's registration and tool catalog are stored in `hand_sockets`, the socket carries its connection ID as an attachment, and a woken object rebuilds its hands from the open sockets before handling anything. Hands' heartbeat pings are WebSocket control frames that the runtime answers without waking the object. `GET /sessions/<name>/hands` lists attached names. A turn's `"hand"` names the machine its Code Mode scripts, and those of the subagents it starts, run on; without it scripts run on the session's configured executor, or on the only attached hand when there is no executor, and otherwise fail and list the attached hands. Inside a script any tool call runs on another attached hand when its arguments include `hand: "<name>"` (freeform tools take `{ input, hand }`), so one script can fan out across machines with `Promise.all` or read on one hand and write on another; the call travels from the script's hand through the session to the target and back, and `tools.hands()` lists the attached hands and the script's own. Selecting a hand writes the session's in-memory executor registry, so no discovery, egress lookup or connection setup sits between admission and execution. Hands attach, reconnect and leave at any time: a reconnecting hand replaces its previous socket; a turn whose hand is absent gets failed cells that dispatched nothing; a call to a hand that is not attached fails without running, so `Promise.allSettled` keeps the other hands' results; and a hand lost mid-call reports an unknown outcome without replay. Nothing waits for a hand: a client attaches its hand before prompting, normally once for its whole session, and submits as soon as the hand is listed. The hand listing includes only hands whose connection the resident SDK can use. A scope opens its runtime in Code Mode only while it has a configured executor, an attached hand or a turn naming a hand; otherwise the model gets the SDK's direct tools for subagents. A turn that changes the mode reopens the resident runtime, and hand connections pass to the new runtime, and to a runtime opened after a failure, without reconnecting, so their Code Mode state survives. Hand frames use `REMOTE_MAX_FRAME_BYTES` and `REMOTE_TIMEOUT_MS`. `scripts/worker-client.mjs --origin <url> --session <name> --hand <name>` submits once the session lists the hand; `-` as the prompt reads one prompt per stdin line and `--timing` reports per-turn connection, acceptance and first-text times.

`node scripts/measure-hands.mjs` builds `nanocode` from the sibling SDK, attaches `nanocode hand` processes to local workerd with the mock provider, and checks that a turn without hands or an executor gets direct tools, one script fanning out to both hands with `Promise.all`, a script writing a file on its own hand and copying it to the other with `apply_patch`, per-turn hand choice, a turn without `hand` failing among two hands and running on the only one, `Promise.allSettled` after one hand is killed, reattachment, brain callbacks and Code Mode state on a hand, a turn naming an executor failing at once with the gateway's 501 and leaving no alarm, a turn naming an absent hand reporting it with one `retrying` event and its alarm at `retry_at` and ending its retries when cancelled, a turn naming a departed hand waiting and then running on it 26 ms after it reattached with `RECOVERY_DELAY_MS` at its production 30 s (`HANDS_RECOVERY_DELAY_MS`), a 45 s idle connection (`HANDS_KEEPALIVE_MS`) staying attached on workerd's ping replies, and both hands staying listed and usable without reconnecting after the session object is evicted. On an Apple Silicon laptop two hands attached 537 ms after process spawn, two concurrent 1 s `exec_command` calls on different hands spanned 1068 ms from first start to last end inside one script, the cross-hand copy turn took 74 ms, a killed hand left the registry within 3 ms, and single-exec turns took 34 ms median from submission to completion.

Codex model calls within a turn, and across turns queued behind it, share one Responses WebSocket. The WASM host transport asks the session Durable Object to open it; the session checks the request's authority and upgrades through egress `/socket` without waiting for storage, because the handshake carries no session state; the durability wait happens before each frame. The session repeats that durability wait and authority check before every frame it sends. After the first call the SDK sends only new input with `previous_response_id`; a replaced socket or a restored session replays the full history. A non-101 handshake uses the safe Codex error projection: 426 moves the resident session to HTTPS at once, and other retryable rejections fall back after the SDK's retry budget. A socket closed upstream between calls is replaced before the next send. An open outbound socket keeps the session Durable Object in memory and billed, and upstream keeps an idle one for about 15 minutes, so when the session has no queued or running turn and no background work it waits `MODEL_SOCKET_LINGER_MS` and then, if it is still idle, closes its model sockets and disposes a runtime whose configured executor connection would otherwise stay open. A turn admitted within the linger reuses the open socket and sends only its new input; one admitted later opens a new socket and replays the full history. The linger is the operator's price for that latency: 30 s keeps the object billed for at most 30 s × 128 MB = 3.75 GB-s after each burst of turns. Local measurements set it to 0. `warm` on the session socket asks the scope's resident runtime, restored from the last turn's descriptor when needed, to open its Responses socket and then starts the linger, so a client that sends it when the user starts typing moves the handshake and the runtime restore off the next turn, which reuses that socket if it arrives within the linger. While a turn is queued or running or background work is pending, `warm` uses the resident runtime as it is, because reopening it in another hands mode, after a hand attached mid-turn, stopped the running turn and repeated its model call; an idle session's `warm` reopens the runtime in the mode the next turn needs. A Claude runtime has no model socket, so `warm` only restores it. The resident runtime itself costs nothing while idle and is reused if the object stays in memory.

WASM linear memory never shrinks, and allocator fragmentation grows it well past the data it holds: a local 60-turn Claude session with a 4 MB conversation held 12.5 MB live between turns and 28 MB at its peak, while its linear memory reached 44 to 50 MB across runs. Several session objects can share one isolate and its 128 MB limit, so when a session goes idle with linear memory above `RUNTIME_MEMORY_BUDGET_BYTES` (64 MiB, half that limit) it disposes the runtime at once instead of lingering, and the next turn opens a fresh instance from storage. Retiring also drops the session's own reference to that instance: before 2026-10-19 it stayed in the map of reader instances until the next request replaced it, so a retired runtime's linear memory stayed allocated while the object idled. Reopening a 4 MB session took about 120 ms locally; with a 20 MiB budget every turn after the 28th reopened and all 60 completed. Session metrics count these as `runtime_retirements`.

Use `node scripts/summarize-timing.mjs output/<report>.json` to inspect a measurement's timing breakdown. Request results retain observed admission, runtime-open, execution and checkpoint timings. Session metrics expose the resident runtime after completion, aggregate host/WASM/bridge timings and the most recent 64 model dispatches, using the existing diagnostic retention policy. Each dispatch includes a runtime ID, dispatch ID, relative start time, header and body timings, byte counts and the egress's diagnostics, including both attempts after a 401; a Codex socket is one entry with `transport: "websocket"` and send and frame counts. SDK display events expose elapsed model-call time; event envelopes identify their host runtime and receive time. SSE adds `streamed_at` at enqueue time, before any platform output gate or network delivery. No tracing RPCs or additional durability barriers are introduced.

Elapsed times use local clocks; never subtract monotonic timestamps from different runtimes or isolates. Production Worker clocks advance only after I/O, so synchronous WASM, parsing and copy timings can be zero despite consuming CPU. Use a local V8 CPU profile for CPU attribution and keep it separate from production network measurements. Aggregate spans overlap and include the resident SDK task tree; a host operation completing during a turn may have started earlier. Turn timing records are observational and can restart at a recovery boundary. A fresh session does not prove a cold isolate, and an enqueue timestamp does not establish when the client received text.
