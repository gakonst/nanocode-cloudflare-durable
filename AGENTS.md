# Development and deployment

This repository is the nanocode Cloudflare Worker: nanocode agents running in Durable Objects, as a library and a default deployment. Its sibling `../nanocodex` supplies the Rust SDK. `sdk-revision.json` records the SDK master revision the Worker builds against; check out that revision in the sibling when preparing a fresh workspace. Keep SDK changes in that workspace and Worker-specific code here. Hosted platform pieces (private egress with credential storage, the vault, execution-host fleets, identity and connectors) live in gakonst/nanocode-platform, which consumes this library. Do not add code comments, README files, Cargo features, wasm-bindgen glue, tests, or test-only dependencies.

`src/index.ts` exports `createNanocode(options)`, which returns the `AgentSession` Durable Object class and the Worker `fetch` handler. The library defines interfaces and ships no adapters. `options.authenticate(request, env)` returns the caller's account ID or `null`; each account's sessions live in separate objects named by `[account, session]`. `options.egress(env)` returns anything with `fetch(request)` that answers the egress contract: `POST /model` with the provider body and the `x-nanocode-model` JSON header `{provider, authority, endpoint, headers, subscription}`, `GET /socket` upgrades for Codex Responses sockets with `x-nanocode-socket`, `GET /remote` upgrades to a configured execution host with `x-nanocode-authority`, and `GET /metrics`. A service binding to a separate Worker satisfies it directly. `MODEL_AUTH` tells the agent whether both providers use subscription or API-key wire compatibility; the optional `options.subscription(account, env, provider)` decides it per account and provider instead, for an egress that holds each account's own credentials. Claude subscription sessions use Claude Code's wire compatibility. Codex subscription sessions use the ChatGPT Responses WebSocket with `OpenAiAuth::host_managed_chatgpt()`, and Codex API-key sessions use the public Responses API at `https://api.openai.com/v1` over HTTPS with `OpenAiAuth::gateway_managed()` and the SDK's default of store: false, so every model call replays the full history and OpenAI retains nothing; Codex subscription sessions also keep store: false, as the ChatGPT backend requires, and continue responses on their socket. The SDK can store and continue API-key responses with `.store(true)`, but measured through AI Gateway storing a response delayed its first byte by about 0.2 s while continuing one saved only request bytes, so the Worker leaves it off. The egress must agree, and a resident runtime reopens when a later turn's mode differs. The library makes no outbound requests itself and holds no credentials.

The default deployment in `worker/` uses Cloudflare AI Gateway through the `AI` binding. `worker/gateway.ts` implements the egress contract with `env.AI.gateway(AI_GATEWAY_ID).run()`: Claude Messages requests go to the gateway's Anthropic provider with only the `accept`, `content-type`, `anthropic-version` and `anthropic-beta` headers, Codex Responses requests go to its OpenAI provider's `responses` endpoint with only `accept` and `content-type`, the gateway supplies the provider key from BYOK or bills through Unified Billing, and the response streams back with provider and `cf-aig-*` headers. Binding requests are pre-authenticated, so the Worker holds no provider key or gateway token. The route parses each body anyway to pass it as the binding's `query`, so it answers with an `x-nanocode-model-diagnostic` of the request's body bytes, input item count and whether it continued a previous response, which session metrics list in `model_diagnostics`. The gateway route carries both providers over HTTPS only: `/socket` answers 426, so Codex keeps to HTTPS, and Codex subscriptions and execution hosts need an egress that serves them, such as the platform's. `worker/index.ts` authenticates one account by comparing the bearer token's SHA-256 with the `ACCESS_TOKEN_SHA256` variable; an empty value rejects every request. Against an account's `default` gateway with no key in the Worker, a deployed Claude turn completed through the binding in 3.4 s of run time. On 2026-10-19 the deployed default Worker completed a Codex turn through the gateway's OpenAI provider in 6.8 s from submission on a new session and 2.1 s on the next turn, and a Claude turn in 5.0 s. A deployed Codex turn of three sequential `list_agents` calls and a reply sends 36.8–43.1 KB on every call, 158 KB and 169 KB per turn; with store: true (SDK b651367, since reverted) it sent 2.1 KB on each continued call, but the median model-call time rose from 1.56 s to 2.15 s. A Claude turn through the same route completed in 4.6 s.

The WASM agent and SQLite checkpoints run inside the same session Durable Object. A stable session UUID is persisted before SDK initialization. Requests are queued durably and deduplicated by `request_id`; reusing an ID with different input returns 409. SDK ownership fences, revision checks, immutable records, model receipts, tool receipts, subagent journals, and checkpoints use the persistent store. No memory store is used for agent state.

Alarms drive work independently of client connections. A watchdog alarm is persisted before execution, using `RECOVERY_DELAY_MS` as an operator recovery policy. Completed requests return saved results. Interrupted model calls may repeat; dispatched tools retain the SDK's uncertain-outcome handling. The Worker does not promise exactly-once model billing or external side effects. Concurrent sessions use independent Durable Objects. Each session executes queued root turns serially, while SDK subagents can run concurrently. Durable background markers keep alarms armed after root requests finish until the SDK task tree, continuation turns, journal writes, and detached remote execution are quiescent. Resume pending SDK operations in accepted order before later requests. Cancellation must settle in the SDK before the queue reports it complete. The `subagent-completion:` request-ID prefix is reserved.

Cloudflare chooses physical Durable Object placement. Agent execution and checkpoint storage are co-located by construction; this does not pin all objects to an exact Cloudflare colo. SQLite access stays inside each session, including the full SDK subagent tree. Reuse the resident WASM instance and SDK session across turns; status and event history must not initialize WASM. Root turns are serial, while SDK children can run concurrently.

The default tool collection omits local machine tools and enables SDK delegation. Shell, filesystem, desktop, and remote Code Mode execution require a separately configured execution host; this Worker does not create a machine environment: hands dial in, and an egress may connect configured execution hosts at `/remote`. Use the SDK RemoteFrame/RemoteOperation protocol for that host, with orchestration and tool receipts remaining in the brain. A machine executor's unrestricted network access is governed by that host; the Worker cannot enforce a proxy for an independently configured machine.

Recovery delay, event page size, event coalescing, the event-stream keepalive interval (`EVENT_STREAM_KEEPALIVE_MS`), the model-socket linger, the runtime memory budget, and execution-host frame and timeout policies are explicit Wrangler variables.

Install Rust 1.97 or newer, the `wasm32-unknown-unknown` target, and Node.js. Run `npm ci`, `cargo check --locked --lib --target wasm32-unknown-unknown`, `npm run check`, and `npm run dry-run`. Run SDK checks from `../nanocodex` with `cargo check --locked --lib` and `cargo check --locked --lib --target wasm32-unknown-unknown`. Local compilation keeps incremental artifacts without debug information. The optimized WASM build uses the `wasm` profile. Dependency resolution is pinned by both lockfiles.

The Rust crate is host glue around the SDK; protocol, turn and event logic belongs upstream. `src/wasm/bridge.rs` is the import and export ABI and its single-threaded executor, and `src/wasm/store.rs` maps the SDK's state store onto the session's SQLite through host calls. `src/wasm/transport.rs` implements `nanocode::http::Sender` once over the `http_start` and `http_read` host calls for both backends, Claude through `SenderTransport` and Codex HTTPS through `host::send_http`, and opens Codex Responses sockets with the handshake headers the SDK builds. `src/remote/runtime.rs` is the `RemoteLink` that carries the SDK's `RemoteClient` frames over `remote_send` and `remote_poll`. `src/wasm/events.rs` encodes `SessionEvents` batches for the `events` host call. `src/wasm.rs` drives the runtime with the SDK's `durable_outcome`, `durable_prompt`, `pending_turns`, `settle`, `select_prompt_hand` and `PLACEMENT_INSTRUCTIONS`. Egress injects provider credentials, so Claude clients send no auth headers and Codex uses `OpenAiAuth::host_managed_chatgpt()`.

Deploy from this directory:

1. Run `npx wrangler login`, or provide `CLOUDFLARE_API_TOKEN` through your secret manager.
2. In AI Gateway, use the `default` gateway or create one and set `AI_GATEWAY_ID`. Add an Anthropic key under Provider Keys with the `default` alias, or load Unified Billing credits; the AI binding consults only the `default` alias.
3. Generate an access token, keep it in your secret manager, and deploy with its digest: `npx wrangler deploy --var ACCESS_TOKEN_SHA256:$(printf %s "$TOKEN" | shasum -a 256 | cut -d' ' -f1)`. Clients and hands send the token itself as `Authorization: Bearer`.
4. `npm run dry-run` builds the WASM and bundles the Worker into `output/deploy` for review.

Requests require `Authorization: Bearer <access token>`. Submit `POST /sessions/<name>/turns` with JSON `{"request_id":"job-1","prompt":"Your instruction","provider":"claude"}`; the response is 202 while queued or running. Poll `GET /sessions/<name>/turns/job-1` for the final result. Repeating the POST with the same input returns the saved result after completion. Cancel with `POST /sessions/<name>/turns/job-1/cancel`. Read bounded event pages at `GET /sessions/<name>/events?after=0&limit=128` and process counters at `GET /sessions/<name>/metrics`. `GET /sessions/<name>/socket?after=<seq>` upgrades to a hibernating session WebSocket that first sends every stored event after the cursor and then each new one as `{"type":"event","seq","request_id","created_at","event"}`. On it the client sends `{"type":"turn",...}` with the turn body and `{"type":"cancel","request_id"}`, answered by `{"type":"turn"|"cancel","request_id","status","body"}` with the HTTP route's status and body, and `{"type":"warm"}`, answered by `{"type":"warm","warmed"}`. The text message `ping` is answered `pong` by the runtime without waking the session. Reconnect with the last `seq` seen as `after`. `scripts/worker-client.mjs` uses this socket and sends `warm` on the first keypress of each interactive prompt. Omit `provider` for Claude Opus 5.5; `"provider":"codex"` selects GPT-6.1 Sol when the egress serves Codex. Provider selection is durable and immutable within each SDK session; choose a new session name to switch providers. `GET /health` reports supported models and the Claude authentication mode; it does not probe provider availability. Subscription requests retain the SDK's pinned wire compatibility. `npm run dev` runs the Worker under Wrangler with the remote AI binding.

Runtime measurements run the bundled Worker in local workerd (Miniflare). `scripts/local-runtime.mjs` wraps the bundle in a shim that gives the Worker and its Durable Objects an in-isolate `AI` binding: its `gateway().run()` checks that the Worker sent no provider credential, adds a stand-in gateway key and forwards the Claude request through a separate upstream Worker to the measurement's mock provider. The Worker itself has no outbound network access in these runs. Run `npm run dry-run` first.

- `node scripts/measure-local.mjs` measures initial and restored turns and receipt replay against a deterministic mock streaming provider, then restarts workerd during inference and verifies recovery, and runs Codex turns through the shim's OpenAI route against a mock that answers each turn with three `list_agents` calls before its reply. It checks that every request sets store: false, sends no `previous_response_id` and carries no provider credential, that each call replays the full history, including across turns, after Durable Object eviction and after a cancelled turn. The idle-session measurement uses Durable Object eviction; the in-flight measurement forces runtime replacement because ordinary eviction waits for active references.
- `node scripts/measure-background.mjs` holds a real SDK child in inference, replaces workerd during the child and root continuation, verifies alarm-only recovery, and cancels an interrupted root before restoration.
- `node scripts/measure-watch.mjs` checks the session socket: backlog replay and resumption from a cursor, live fan-out of turns submitted over the socket and over HTTP, `warm`, cancellation over the socket, watchers staying connected while the idle object is evicted and resuming when a socket turn wakes it, the runtime ping auto-response, and the close handshake.
- `WORKER_TOKEN=<access token> node scripts/measure-codex-history.mjs <origin> [--turns 2] [--idle <seconds>]` runs Codex turns against a deployment, each asking for three sequential `list_agents` calls so the history grows, optionally waits and runs one more turn, and writes each model call's request bytes, input items, `previous_response_id` use, replay mode, latency and cached input tokens, and each turn's host runtimes, from session metrics and events to `output/`. `--session` and `--prefix` continue an existing session with new request IDs.
- `node scripts/benchmark-transfer.mjs 65536 256` compares JSON byte-array round trips with the raw memory copy used by the WASM HTTP body bridge for 16 MiB of data. This isolates serialization cost, not inference throughput or full application speed. Chunk size and count are benchmark inputs.

For isolated SDK verification, `NANOCODE_WASM_PATH` selects the compiled WASM used by Miniflare measurements.

Keep all reports and generated bundles in ignored `output/`, `dist/`, and `target/`. Local workerd latency does not establish production colo latency. First-time optimized builds, cached builds, mock-provider overhead, and live model latency are separate measurements.

Turn admission commits the queue entry, background marker, stable UUID, and watchdog before starting the resident pump through `waitUntil`. Alarms remain the independent recovery driver. The normal path reuses the already committed watchdog and marker; recovery recommits them before SDK initialization. `Accept: text/event-stream` on the owner turn POST returns a finite, request-scoped durable stream through its terminal result. Disconnecting that stream does not cancel execution. The existing GET event stream includes the full SDK tree. An `after` cursor beyond a saved terminal event returns an empty finite stream.

Hot-path writes do not wait for storage confirmation one at a time. Model dispatch, model socket frames, and executor and hand frames each await `storage.sync()` first, so every earlier write, including SDK receipts, checkpoints and the admitted job, is durable before that effect leaves the session. A tool call one hand's script forwards to another hand, and its result returning to that script, skip the wait: they carry only the hands' own input and output, and the brain keeps no receipt for them. Responses and streamed events are held by Durable Object output gates until earlier writes are confirmed. A turn therefore pays one confirmation wait before its first model request instead of one per write, and a crash before confirmation loses only work that nothing outside the session has observed. In production that single wait averaged 42 ms for Claude and 52 ms for Codex turns, replacing an admission sync, a running-state sync and a sync per checkpoint and event batch before the first dispatch.

Durable Objects bill wall-clock time while an object is handling work or holding a non-hibernatable WebSocket, and SQLite bills every written row including each index entry. Keep both off idle sessions and out of the per-event path. An event-stream response keeps the session object active and billed for as long as it is open, because the object writes to it. The session socket is accepted through the hibernation API, so an idle connected client costs nothing and the object is evicted as if none were attached; prefer it for clients that stay connected. Each watcher's authority is a row in `watch_sockets` and its cursor is in the socket attachment, so events reach watchers after the object is restored. Events are one row each with `seq` as the plain integer primary key: no secondary index and no `AUTOINCREMENT` counter, and sessions created before that keep their table but drop its indexes. Turn streams start from the job's recorded `first_seq` and finished turns record `last_seq`, so per-turn reads scan the primary key from the turn's own events. Codex raw provider frames (`api.event`) are not emitted, as in the native CLI; they were most event rows and bytes. The SDK's `SessionEvents` pump sends the first event after a quiet period at once and then at most one batch per `EVENT_COALESCE_MS`, an operator policy for how often a streaming client sees new text (100 ms, ten updates a second), and merges consecutive assistant and reasoning-summary deltas of the same item into one event. A turn that waits for its events to drain flushes immediately, so coalescing never delays a result. Model request bodies and Codex socket frames cross from WASM as raw bytes through the `dispatch_body` import, and the session forwards a model body to egress unchanged with its routing in the `x-nanocode-model` header, so a large request is not JSON-escaped and parsed again on the way out. Event coalescing then halved rows written per turn in a local 20-turn run with 40 text deltas per reply, from 81.6 to 42.9, and cut bridge event calls from 945 to 89. A CPU profile of a 110-turn local session with 200 deltas per reply (`INSPECT=<port>` in a profiling harness with an unstripped build) found software SHA-256 in 38% of samples; with the SDK's BLAKE3 record keys WASM CPU per turn fell from 173.5 ms to 20.7 ms and storage from 19.1 MB to 12.1 MB. Session metrics report `database_bytes`, the object ID for analytics, and the resident runtime's `wasm_memory_bytes`. The `wasm` profile uses `opt-level = "s"`: on the same 110-turn run, two runs each measured WASM CPU per turn at 24.0 and 30.5 ms with `"z"` (7.39 MB, 2.31 MB gzipped), 19.1 and 17.8 ms with `"s"` (8.01 MB, 2.48 MB) and 8.4 and 18.7 ms with `3` (10.51 MB, 3.39 MB); `"s"` keeps most of the CPU saving without the larger module every cold start of a hibernated session compiles.

Hands are machines that dial a session so its scripts can use them, such as the laptop where a prompt was typed. A hand is the whole machine under a name, not a workspace: `nanocode hand wss://<host>/sessions/<name>/hands` with the access token in `NANOCODE_RUNNER_TOKEN` attaches the calling machine under its host name, and `--name` or a final `/hands/<name>` path segment names it otherwise. Every session accepts hands. The socket terminates in the session Durable Object through the WebSocket Hibernation API, so an idle attached hand does not keep the object in memory or billed: each hand's registration and tool catalog are stored in `hand_sockets`, the socket carries its connection ID as an attachment, and a woken object rebuilds its hands from the open sockets before handling anything. Hands' heartbeat pings are WebSocket control frames that the runtime answers without waking the object. `GET /sessions/<name>/hands` lists attached names. A turn's `"hand"` names the machine its Code Mode scripts, and those of the subagents it starts, run on; without it scripts run on the session's configured executor, or on the only attached hand when there is no executor, and otherwise fail and list the attached hands. Inside a script any tool call runs on another attached hand when its arguments include `hand: "<name>"` (freeform tools take `{ input, hand }`), so one script can fan out across machines with `Promise.all` or read on one hand and write on another; the call travels from the script's hand through the session to the target and back, and `tools.hands()` lists the attached hands and the script's own. Selecting a hand writes the session's in-memory executor registry, so no discovery, egress lookup or connection setup sits between admission and execution. Hands attach, reconnect and leave at any time: a reconnecting hand replaces its previous socket; a turn whose hand is absent gets failed cells that dispatched nothing; a call to a hand that is not attached fails without running, so `Promise.allSettled` keeps the other hands' results; and a hand lost mid-call reports an unknown outcome without replay. Nothing waits for a hand: a client attaches its hand before prompting, normally once for its whole session, and submits as soon as the hand is listed. The hand listing includes only hands whose connection the resident SDK can use. A scope opens its runtime in Code Mode only while it has a configured executor, an attached hand or a turn naming a hand; otherwise the model gets the SDK's direct tools for subagents. A turn that changes the mode reopens the resident runtime, and hand connections pass to the new runtime, and to a runtime opened after a failure, without reconnecting, so their Code Mode state survives. Hand frames use `REMOTE_MAX_FRAME_BYTES` and `REMOTE_TIMEOUT_MS`. `scripts/worker-client.mjs --origin <url> --session <name> --hand <name>` submits once the session lists the hand; `-` as the prompt reads one prompt per stdin line and `--timing` reports per-turn connection, acceptance and first-text times.

`node scripts/measure-hands.mjs` builds `nanocode` from the sibling SDK, attaches `nanocode hand` processes to local workerd with the mock provider, and checks that a turn without hands or an executor gets direct tools, one script fanning out to both hands with `Promise.all`, a script writing a file on its own hand and copying it to the other with `apply_patch`, per-turn hand choice, a turn without `hand` failing among two hands and running on the only one, `Promise.allSettled` after one hand is killed, reattachment, brain callbacks and Code Mode state on a hand, a departed hand failing its cell at once, a 45 s idle connection (`HANDS_KEEPALIVE_MS`) staying attached on workerd's ping replies, and both hands staying listed and usable without reconnecting after the session object is evicted. On an Apple Silicon laptop two hands attached 537 ms after process spawn, two concurrent 1 s `exec_command` calls on different hands spanned 1068 ms from first start to last end inside one script, the cross-hand copy turn took 74 ms, a killed hand left the registry within 3 ms, and single-exec turns took 34 ms median from submission to completion.

Codex model calls within a turn, and across turns queued behind it, share one Responses WebSocket. The WASM host transport asks the session Durable Object to open it; the session checks the request's authority and upgrades through egress `/socket` without waiting for storage, because the handshake carries no session state; the durability wait happens before each frame. The session repeats that durability wait and authority check before every frame it sends. After the first call the SDK sends only new input with `previous_response_id`; a replaced socket or a restored session replays the full history. A non-101 handshake uses the safe Codex error projection: 426 moves the resident session to HTTPS at once, and other retryable rejections fall back after the SDK's retry budget. A socket closed upstream between calls is replaced before the next send. An open outbound socket keeps the session Durable Object in memory and billed, and upstream keeps an idle one for about 15 minutes, so when the session has no queued or running turn and no background work it waits `MODEL_SOCKET_LINGER_MS` and then, if it is still idle, closes its model sockets and disposes a runtime whose configured executor connection would otherwise stay open. A turn admitted within the linger reuses the open socket and sends only its new input; one admitted later opens a new socket and replays the full history. The linger is the operator's price for that latency: 30 s keeps the object billed for at most 30 s × 128 MB = 3.75 GB-s after each burst of turns. Local measurements set it to 0. `warm` on the session socket asks the scope's resident runtime, restored from the last turn's descriptor when needed, to open its Responses socket and then starts the linger, so a client that sends it when the user starts typing moves the handshake and the runtime restore off the next turn, which reuses that socket if it arrives within the linger. A Claude runtime has no model socket, so `warm` only restores it. The resident runtime itself costs nothing while idle and is reused if the object stays in memory.

WASM linear memory never shrinks, and allocator fragmentation grows it well past the data it holds: a local 60-turn Claude session with a 4 MB conversation held 12.5 MB live between turns and 28 MB at its peak, while its linear memory reached 44 to 50 MB across runs. Several session objects can share one isolate and its 128 MB limit, so when a session goes idle with linear memory above `RUNTIME_MEMORY_BUDGET_BYTES` (64 MiB, half that limit) it disposes the runtime at once instead of lingering, and the next turn opens a fresh instance from storage. Reopening a 4 MB session took about 120 ms locally; with a 20 MiB budget every turn after the 28th reopened and all 60 completed. Session metrics count these as `runtime_retirements`.

Use `node scripts/summarize-timing.mjs output/<report>.json` to inspect a measurement's timing breakdown. Request results retain observed admission, runtime-open, execution and checkpoint timings. Session metrics expose the resident runtime after completion, aggregate host/WASM/bridge timings and the most recent 64 model dispatches, using the existing diagnostic retention policy. Each dispatch includes a runtime ID, dispatch ID, relative start time, header and body timings, byte counts and the egress's diagnostics, including both attempts after a 401; a Codex socket is one entry with `transport: "websocket"` and send and frame counts. SDK display events expose elapsed model-call time; event envelopes identify their host runtime and receive time. SSE adds `streamed_at` at enqueue time, before any platform output gate or network delivery. No tracing RPCs or additional durability barriers are introduced.

Elapsed times use local clocks; never subtract monotonic timestamps from different runtimes or isolates. Production Worker clocks advance only after I/O, so synchronous WASM, parsing and copy timings can be zero despite consuming CPU. Use a local V8 CPU profile for CPU attribution and keep it separate from production network measurements. Aggregate spans overlap and include the resident SDK task tree; a host operation completing during a turn may have started earlier. Turn timing records are observational and can restart at a recovery boundary. A fresh session does not prove a cold isolate, and an enqueue timestamp does not establish when the client received text.
