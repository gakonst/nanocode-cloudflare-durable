# Development and deployment

This repository is nanocode-cloudflare-durable (gakonst/nanocode-cloudflare-durable, formerly nanocode-worker): nanocode agents running in Durable Objects, as a library and a default deployment, the Cloudflare counterpart of gakonst/nanocode-vercel-durable. gakonst/nanocode-ts supplies the agent runtime, the Rust SDK compiled into one WebAssembly module with its host-agnostic TypeScript host and its Cloudflare adapter, as the git dependency `github:gakonst/nanocode-ts#<commit>` that `package-lock.json` pins. The package commits its compiled `dist/`, so this repository builds no Rust: move the commit with `npm install nanocode-ts@github:gakonst/nanocode-ts#<commit>` after merging a change there, and read the SDK revision it builds against in its `sdk-revision.json`. Keep SDK changes in the SDK, host-agnostic bridge changes and generic Durable Object plumbing in nanocode-ts and Cloudflare business logic here. The `../nanocode-worker` path is a symlink to this checkout for consumers that still name it. Hosted platform pieces (private egress with credential storage, the vault, execution-host fleets, identity and connectors) live in gakonst/nanocode-platform, which consumes this library. Do not add code comments, README files, Cargo features, wasm-bindgen glue, tests, or test-only dependencies.

`src/index.ts` exports `createNanocode(options)`, which returns the `AgentSession` Durable Object class and the Worker `fetch` handler. The library defines interfaces and ships no adapters. `options.authenticate(request, env)` returns the caller's account ID, `{account, read_only: true}` for a caller that may only read, or `null`; each account's sessions live in separate objects named by `[account, session]`. A read-only caller gets 403 for every session request other than GET and for attaching a hand, and its session socket streams events but answers `turn` and `cancel` with 403 and `warm` with `warmed: false`. A principal may also carry `grant`, a JSON value the host defines, and `expires_at`, its credential's expiry in milliseconds since the epoch. The session keeps both with each turn the caller submits, with its session socket's registration and with its hand's `hand_sockets` row, and passes the grant of the turn it is running to host tool calls. Sockets and event streams outlive the request that authenticated them, so the session checks the caller before it admits each session socket message, before it delivers events to a watcher, before each read of an event stream and before each frame it sends to a hand or accepts from one, in arrival order: past `expires_at`, or when the optional `options.active(account, grant, env)` returns false or throws, it sends the session socket `{"type":"error","error":"access token expired or revoked"}` and closes it with 1008, ends the event stream, or disposes the hand connection, which fails the cell that was being sent as not dispatched and detaches the hand. Event delivery runs the `active` check in the background, so a watcher can receive the batch published while its first failing check runs; hosts that cache the answer bound how long a revocation takes beyond that. The error frame arrives at once, but a close issued outside the socket's own message handler reached the client about 10 s later in local workerd and 42 s later in production, while one issued from its message handler arrived within 319 ms in production. `options.egress(env)` returns anything with `fetch(request)` that answers the egress contract: `POST /model` with the provider body and the `x-nanocode-model` JSON header `{provider, authority, endpoint, headers, subscription}`, `GET /socket` upgrades for Codex Responses sockets with `x-nanocode-socket`, `GET /remote` upgrades to a configured execution host with `x-nanocode-authority`, and `GET /metrics`. A service binding to a separate Worker satisfies it directly. `MODEL_AUTH` tells the agent whether both providers use subscription or API-key wire compatibility; the optional `options.subscription(account, env, provider)` decides it per account and provider instead, for an egress that holds each account's own credentials. The optional `options.recordSession(account, name, env)` lets a host keep an index of each account's sessions: a session object calls it before handling its first request and, once it returns true, writes a `recorded` metadata row and never calls it again, so sessions created earlier are indexed on their next request; false means the account no longer exists, and the session deletes its storage and answers 403. The returned `deleteSession(account, name, env)` calls the session object's internal delete route, which the public routes cannot reach: it closes the session's hand and watcher sockets, disposes its runtimes and their model sockets, deletes its alarm and all of its storage, and the instance answers 410 until it is evicted and opens no WASM instance meanwhile, since the recovery note of a turn that was running when the session was deleted recreated the turn log's tables in the emptied storage. Claude subscription sessions use Claude Code's wire compatibility. Codex subscription sessions use the ChatGPT Responses WebSocket with `OpenAiAuth::host_managed_chatgpt()`, and Codex API-key sessions use the public Responses API at `https://api.openai.com/v1` over HTTPS with `OpenAiAuth::gateway_managed()` and the SDK's default of store: false, so every model call replays the full history and OpenAI retains nothing; Codex subscription sessions also keep store: false, as the ChatGPT backend requires, and continue responses on their socket. The SDK can store and continue API-key responses with `.store(true)`, but measured through AI Gateway storing a response delayed its first byte by about 0.2 s while continuing one saved only request bytes, so the Worker leaves it off. The egress must agree, and a resident runtime reopens when a later turn's mode differs. The library makes no outbound requests itself and holds no credentials.

The default deployment in `worker/` uses Cloudflare AI Gateway through the `AI` binding. `worker/gateway.ts` implements the egress contract through the binding: Claude Messages requests go to `env.AI.run("anthropic/<model>", body, { gateway: { id: AI_GATEWAY_ID }, returnRawResponse: true })` with only the `accept`, `content-type`, `anthropic-version` and `anthropic-beta` headers, and Codex Responses requests go to `env.AI.gateway(AI_GATEWAY_ID).run()` at its OpenAI provider's `responses` endpoint with only `accept` and `content-type`. The gateway supplies the provider key from the BYOK key stored under its `default` alias or bills the account's Unified Billing credits, and the response streams back with provider and `cf-aig-*` headers. Claude goes through `env.AI.run` because on 2026-10-21 the gateway's Anthropic passthrough (`gateway().run()` with provider `anthropic`) sent no key to Anthropic on a gateway without a BYOK key, which answered `401 x-api-key header is required`, even in Tempo Development Resources with $499.95 of credits, while `env.AI.run` and the REST `/ai/v1/messages` endpoint billed the credits and streamed Messages events with tools, `cache_control` and `anthropic-beta` intact. That path names models as Cloudflare's catalog does, `anthropic/claude-haiku-5.5` for Anthropic's `claude-haiku-5-5`, and answers `not_found_error` for `anthropic/claude-haiku-5-5`, so the egress rewrites the request's model from Anthropic's form to the catalog's (`-5-5` to `-5.5`), and responses still name Anthropic's model. The local runtime's `AI` shim implements both calls and reverses that rename before the mock provider sees the request. Binding requests are pre-authenticated, so the Worker holds no provider key or gateway token. The route parses each body anyway to pass it as the binding's `query`, so it answers with an `x-nanocode-model-diagnostic` of the request's body bytes, input item count and whether it continued a previous response, which session metrics list in `model_diagnostics`. The gateway route carries both providers over HTTPS only: `/socket` answers 426, so Codex keeps to HTTPS, and Codex subscriptions and execution hosts need an egress that serves them, such as the platform's; `/remote` answers 501, so a turn naming an executor fails at once with that answer as its error. `worker/index.ts` authenticates one account by comparing the bearer token's SHA-256 with the `ACCESS_TOKEN_SHA256` variable; an empty value rejects every request. Against an account's `default` gateway with no key in the Worker, a deployed Claude turn completed through the binding in 3.4 s of run time. On 2026-10-19 the deployed default Worker completed a Codex turn through the gateway's OpenAI provider in 6.8 s from submission on a new session and 2.1 s on the next turn, and a Claude turn in 5.0 s. A deployed Codex turn of three sequential `list_agents` calls and a reply sends 36.8–43.1 KB on every call, 158 KB and 169 KB per turn; with store: true (SDK b651367, since reverted) it sent 2.1 KB on each continued call, but the median model-call time rose from 1.56 s to 2.15 s. A Claude turn through the same route completed in 4.6 s.

The default deployment is also the example app, the Cloudflare counterpart of nanocode-vercel-durable's. Wrangler serves `public/` as static assets before the Worker runs, so `/` (`index.html`, a chat in the nanocode.xyz design whose `style.css` and Commit Mono fonts are copied from nanocode-vercel-durable) and `/how-it-works` need no token, while every `/sessions` request does. Both pages carry nanocode.xyz's numbered navigation (gakonst/nanocode-site's `src/Nav.ts`) with absolute links, Experiments current and its menu of experiments opening on hover or keyboard focus with this demo current, so copy changes to the site's navigation into both pages. `public/app.js` keeps the access token, the session, its model and its effort in localStorage, submits each prompt as `POST /sessions/<name>/turns` with `Accept: text/event-stream`, the model and the effort and reads `GET /sessions/<name>/events?after=<last seq>` again until its turn's `result` arrives, so a reset during the turn only pauses the transcript. As nanocode-vercel-durable's chat does, it streams the paragraph being written behind a caret, shows reasoning summaries as `thinking` entries, reveals text on a 16 ms timer at 1 − e^(−t/100 ms) of what is not yet shown so Claude's bursts after summarized thinking stream too, shows a model and effort picker until the session starts, and takes `/model [words]` (a new session with the first Claude model whose names contain every word, or the picker) and `/effort [level]` (the effort of the next turns, or a row of the model's levels). `worker/tools.ts` adds the `charge` host tool, which logs `{"charge":{session,amount,memo,at}}` and waits `CHARGE_CONFIRM_MS` (3 s) before it answers, so the crash button has an effect to interrupt. `createNanocode({ chaos: true })` enables `POST /sessions/<name>/crash` with `{"after_ms"}`, which arms the session object to call `ctx.abort` `after_ms` after its next host tool call starts; without `chaos` the route answers 404. The deployment sets `RECOVERY_DELAY_MS` to 5 s instead of 30 s so a reset turn resumes within 5 s: the pump arms the alarm when it starts and again each time the alarm fires while it runs, so the alarm fires at most `RECOVERY_DELAY_MS` after a reset. With `CHAT_PUBLIC` set to `1`, `worker/index.ts` lets callers without the access token in as the `public` account, whose sessions are separate from the owner's: they may reach only `/health` and a session's `turns`, `turns/<id>`, `turns/<id>/cancel`, `events` and `crash` routes, with a 403 for every other route, such as `/metrics`, the session socket and hands. Each of their session requests must pass the `PublicLimit` Durable Object (`worker/limit.ts`) named by the caller's `cf-connecting-ip`, or by its /64 for IPv6, the prefix of one subscriber network within which privacy addresses rotate (RFC 8981): it keeps a fixed 60 s window of 30 requests in its synchronous KV storage, the Vercel demo's firewall budget, and answers 429 beyond it. A turn's prompt may hold 2,000 characters (413 beyond), its provider must be Claude, its model Claude Haiku 5.5, the cheapest the demo can run, and its effort one Haiku takes, the levels the SDK's `ModelCapabilities` allow at SDK 3d06bdf91 (403 otherwise). The demo does not offer open-weight models as nanocode-vercel-durable's does: on 2026-10-20 none of Workers AI's 22 tool-calling text models took the Anthropic Messages API (each answered "Anthropic Messages API is not supported for model"), and its `/ai/v1/responses` rejected the SDK's Codex requests for GLM-5.3 and Kimi K2.6 with schema errors and answered gpt-oss-120b with events that are not Responses events, so running them needs the SDK's Chat Completions gateway, which is native-only, in WebAssembly with a Workers AI provider. The Workers Rate Limiting binding came first and enforced nothing: on 2026-10-21 in production (SJC), with a limit of 30 per 60 s, 100 of 100 requests from one IPv4 address within 15 s passed it, while local workerd refused the 31st; Cloudflare documents the binding as permissive and eventually consistent. The optional `CLAUDE_MODEL` variable selects the model of Claude sessions and `/health` reports it; without it the SDK's default, Claude Opus 5.5, applies. `public/app.js` reads the model from `/health` and hides the token field when `/health` answers without a token. `npm run deploy:demo` deploys the public demo as the separate Worker `nanocode-cloudflare-durable` in Cloudflare's Tempo Development Resources account (`CLOUDFLARE_ACCOUNT_ID=0a39052b0a32ba8c8444345fe21b7595`), https://nanocode-cloudflare-durable.tempo-dev.workers.dev, with `CHAT_PUBLIC=1`, `CLAUDE_MODEL=claude-haiku-5-5`, `AI_GATEWAY_ID=nanocode-cloudflare-durable` and no access token; it needs a Wrangler login with access to that account. Its pages, `style.css` and `app.js` use relative URLs, so the same deployment also serves at https://nanocode.xyz/cloudflare/: gakonst/nanocode-site's Worker, in the same account, forwards `/cloudflare/*` through a service binding with the prefix removed and the visitor's headers, `cf-connecting-ip` included, so `PublicLimit` limits each visitor as it does on workers.dev, and prefixes the `Location` of its redirects. nanocode-site also binds this Worker's `PublicLimit` class for its nanocode.xyz/vercel proxy, naming objects `vercel:<client>`, so renaming the class or `client` changing its keys breaks that binding. The `nanocode-cloudflare-durable` gateway there holds no provider key, so the demo's model requests spend the account's Unified Billing credits. `npm run deploy` still updates the token-only `nanocode` Worker in whichever account the login selects. On 2026-10-21 the deployed demo completed a new session's first Haiku turn in 3.5 s and the next in 1.1 s from submission, and a turn whose object was reset 1.5 s into the charge in 7.3 s, with one charge logged and the model told that its outcome is unknown. `npm run drill` (`scripts/drill.mjs`) runs the bundle on local workerd with a mock Claude provider, arms a crash 1.5 s into the charge, follows the turn as the app does and checks that the object reset, the turn completed, the charge ran once, the model asked for it once and received the unknown-outcome result; it writes `output/drill.json`. On 2026-10-20, with the local runtime's 1 s alarm, the stream ended at the reset 2.0 s after submission and the turn completed at 2.5 s.

The WASM agent and SQLite checkpoints run inside the same session Durable Object. A stable session UUID is persisted before SDK initialization. Turns are queued durably in the SDK's turn inbox and deduplicated by `request_id`; reusing an ID with different input returns 409. SDK ownership fences, revision checks, immutable records, model receipts, tool receipts, subagent journals, and checkpoints use the persistent store. No memory store is used for agent state.

Alarms drive work independently of client connections. A watchdog alarm is persisted before execution, using `RECOVERY_DELAY_MS` as an operator recovery policy. Completed requests return saved results. Interrupted model calls may repeat; dispatched tools retain the SDK's uncertain-outcome handling. The Worker does not promise exactly-once model billing or external side effects. Concurrent sessions use independent Durable Objects. Each session executes queued root turns serially, while SDK subagents can run concurrently. Durable background markers keep alarms armed after root requests finish until the SDK task tree, continuation turns, journal writes, and detached remote execution are quiescent. Resume pending SDK operations in accepted order before later requests. Cancellation must settle in the SDK before the queue reports it complete, except for a turn whose runtime cannot open, which finishes cancelled at once and which the SDK cancels on admission when the runtime next opens, and a turn whose cancellation was requested when its drive fails, which finishes cancelled the same way: a turn whose drive fails every time, such as one whose events could not be logged before the SDK replaced oversized ones, otherwise recovered every `RECOVERY_DELAY_MS` forever while every later turn stayed queued, and cancelling it changed nothing. The SDK reserves the `subagent-completion:` request-ID prefix for its own continuation turns, and admission answers 400 for it.

A turn waits instead of running while its execution host is unavailable: when the runtime for it cannot open, or it names a `hand` that is not attached, the pump classifies the failure from its signal and does not guess. Permanent failures finish the turn as failed with `error` and `kind` in its result, so a client's wait ends: a non-101 answer from egress `/remote` with a 4xx status other than 408 and 429, which is `unauthorized` for 401 and 403 and `rejected` otherwise, a 501 (`rejected`), and a runtime configuration the SDK refuses while building it (`configuration`, which `init` answers as a rejection). Everything else is transient and keeps the turn queued, or running for a recovered turn, under `RECOVERY_DELAY_MS`: a 5xx other than 501, 408 or 429 from `/remote` (`unavailable`), no HTTP answer, the `REMOTE_TIMEOUT_MS` connection deadline or a socket closed before its catalog (`unreachable`), an absent hand (`detached`) and any other open failure (`runtime`). The SDK session log's `retry` keeps the message, kind, attempt count and next retry time on the turn, its status report shows them as `error`, `kind`, `attempts` and `retry_at`, and its event stream gets a `retrying` event when the error first appears or changes, not on every retry. A hand attaching starts a turn waiting for it at once. Cancelling a waiting turn finishes it, and session metrics report the pending alarm as `alarm_at`, `null` once nothing is left to retry. The pump commits the background marker only once a queued turn's runtime has opened, so a turn whose runtime never opened leaves nothing retrying after it fails or is cancelled; with no unfinished turn, a permanent failure drops an existing marker and a transient one keeps retrying for the SDK's background work.

Cloudflare chooses physical Durable Object placement. Agent execution and checkpoint storage are co-located by construction; this does not pin all objects to an exact Cloudflare colo. SQLite access stays inside each session, including the full SDK subagent tree. Reuse the resident WASM instance and SDK session across turns. Status, a queued turn's cancellation and event history read through the SDK's session log on a WASM instance without opening the SDK session (instantiating the compiled module took 0.3 ms locally), and opening the session later reuses that instance. Root turns are serial, while SDK children can run concurrently.

The default tool collection omits local machine tools and enables SDK delegation. Shell, filesystem, desktop, and remote Code Mode execution require a separately configured execution host; this Worker does not create a machine environment: hands dial in, and an egress may connect configured execution hosts at `/remote`. Use the SDK RemoteFrame/RemoteOperation protocol for that host, with orchestration and tool receipts remaining in the brain. A machine executor's unrestricted network access is governed by that host; the Worker cannot enforce a proxy for an independently configured machine.

Recovery delay, event page size, the event tail's byte bound, event coalescing, the event-stream keepalive interval (`EVENT_STREAM_KEEPALIVE_MS`), the model-socket linger, the runtime memory budget, and execution-host frame and timeout policies are explicit Wrangler variables.

Install Node.js. Run `npm ci`, `npm run check`, and `npm run dry-run`; `npm run build` type-checks too. The Worker has no Rust of its own and builds none: the bundle imports the package's committed module as `nanocode-ts/nanocode_wasm.wasm`. Run the package's checks in gakonst/nanocode-ts and SDK checks from `../nanocodex` with `cargo check --locked --lib` and `cargo check --locked --lib --target wasm32-unknown-unknown`. `package-lock.json` pins the Worker's npm dependencies, nanocode-ts's commit included.

The package's `AgentRuntime`, `EventHub` and `RemoteExecutor`, its bridge ABI and command table are documented in nanocode-ts's `AGENTS.md`; protocol, turn and event logic belongs in the SDK and host-agnostic glue in the package. The session Durable Object supplies the package's host interfaces. `src/store.ts` is its `SqlHost`, the package's `DurableObjectSql` (`nanocode-ts/cloudflare`) with the Worker's metrics as its observer: it runs each `store` or `log` operation's statements in one `transactionSync` and answers with each statement's rows; metrics count the two separately (`checkpoints` and `log`). The SDK owns the `states`, `owners`, `records`, `turns` and `events` tables, their fencing, revisions and record immutability, turn states and event sequence; the Worker only reads their row counts for metrics. Model requests go to egress `/model`; Codex Responses sockets upgrade through egress `/socket`, and the session accepts the WebSocket and hands it to the package with the egress's `x-nanocode-stream-idle-ms` deadline. `src/remote.ts` dials a configured execution host through egress `/remote` with `RemoteExecutor.connect` and throws `ExecutorRejection` with the status of a refused upgrade, and hands attach through the hibernation API with `RemoteExecutor.accept` and `restore`, so frames stay opaque, `REMOTE_MAX_FRAME_BYTES` is enforced and each hand's catalog text is kept for hibernation. The package flags each batch that holds a request the SDK's `RemoteFrame::dispatches` marks as starting work, so the session refuses that batch once the turn's cancellation is requested without decoding frames. Two commands run on the scope's WASM instance without opening the SDK session: `catalog` reads the name a hand advertises in its catalog, and `admit` asks the SDK's `admit_prompt` whether a turn may enter the inbox, so admission takes the reserved request-ID prefix and the provider rule from the SDK. Each logged event batch reaches the session's `published` callback with `host_timing`, the session answers a finished turn's timings through `finishing`, and the SDK selects each turn's hand with `select_prompt_hand`; turn states, the queue, cancellation before and during a turn, resumption in accepted order, event attribution and quiescence live in the SDK. Egress injects provider credentials, so Claude clients send no auth headers and Codex uses `OpenAiAuth::host_managed_chatgpt()`.

Hosts add their own tools through `createNanocode({ tools: { definitions, call } })`. Each definition's `name`, `description` and JSON Schema `parameters` reach the runtime when it opens, and the package registers them as the SDK's `FunctionTool`s beside the SDK's own tools, offered directly or inside Code Mode scripts. A call crosses the bridge as the `tool_call` host operation; the session Durable Object takes the durability wait it takes before any external effect, refuses it once the turn's cancellation is requested, and awaits `call({ authority, name, input, grant }, env, signal)`, whose result becomes the tool output and whose thrown error a tool error. `grant` is the grant of the turn the session is running, read from its `background:<scope>` row, which holds that turn's descriptor until the runtime settles, so subagents and other background work that continue after a turn run with the grant of the latest turn the session started, and turns submitted before grants existed carry none. The SDK keeps the call's receipt like any tool's, so an interrupted call reports an unknown outcome instead of running again, and session metrics count `host_tool_calls`. Whatever the host keeps out of the result never enters WASM memory, checkpoints or events; the platform serves its credential tools this way so injected secrets stay in its egress.

Deploy from this directory:

1. Run `npx wrangler login`, or provide `CLOUDFLARE_API_TOKEN` through your secret manager.
2. In AI Gateway, use the `default` gateway or create one and set `AI_GATEWAY_ID`. Add an Anthropic key under Provider Keys with the `default` alias, or load Unified Billing credits; the AI binding consults only the `default` alias.
3. Generate an access token, keep it in your secret manager, and deploy with its digest: `npx wrangler deploy --var ACCESS_TOKEN_SHA256:$(printf %s "$TOKEN" | shasum -a 256 | cut -d' ' -f1)`. Clients and hands send the token itself as `Authorization: Bearer`.
4. `npm run dry-run` bundles the Worker and its `public/` assets into `output/deploy` for review. Wrangler adds files to an existing output directory without removing old ones, so bundle into a fresh directory, such as `--outdir output/deploy-ts`, when `output/deploy` holds a bundle from before the nanocode-ts move, and point `NANOCODE_BUNDLE_PATH` at it.

Requests require `Authorization: Bearer <access token>`. Submit `POST /sessions/<name>/turns` with JSON `{"request_id":"job-1","prompt":"Your instruction","provider":"claude"}`; the response is 202 while queued or running. Poll `GET /sessions/<name>/turns/job-1` for the final result; while the turn waits on an unavailable execution host the report adds `error`, `kind`, `attempts` and `retry_at`. Repeating the POST with the same input returns the saved result after completion. A turn may also name a `model`, which the session's first accepted turn binds like its provider (a different one later answers 409; sessions created before the binding count as bound to the deployment's model), and a reasoning effort `thinking` (`none`, `low`, `medium`, `high`, `xhigh` or `max`, 400 otherwise) that the session object applies with nanocode-ts's `setThinking` (since ddff939) before it drives that turn; an effort the session's model does not take fails the turn with kind `configuration` and the SDK's message. Model diagnostics report each request's `model` and `effort`. Cancel with `POST /sessions/<name>/turns/job-1/cancel`. Read bounded event pages at `GET /sessions/<name>/events?after=0&limit=128` and process counters at `GET /sessions/<name>/metrics`. Event streams resume after the larger of `after` and the `Last-Event-ID` header that Server-Sent Events clients send when they reconnect, and only `turns` and `hands` take a further path segment, so `/cancel` cancels only under `/turns/<id>`. A turn whose prompt the session log cannot store within the SQLite value limit, counting its input.accepted event, gets 413 with the `bytes` it needs and the `limit`, and a request body above the limit gets 413 before it is read. HEAD on a GET route answers as GET without a body. `GET /sessions/<name>/socket?after=<seq>` upgrades to a hibernating session WebSocket that first sends every stored event after the cursor and then each new one as `{"type":"event","seq","request_id","created_at","event"}`. On it the client sends `{"type":"turn",...}` with the turn body and `{"type":"cancel","request_id"}`, answered by `{"type":"turn"|"cancel","request_id","status","body"}` with the HTTP route's status and body, and `{"type":"warm"}`, answered by `{"type":"warm","warmed"}`. The text message `ping` is answered `pong` by the runtime without waking the session. Reconnect with the last `seq` seen as `after`. `scripts/worker-client.mjs` uses this socket and sends `warm` on the first keypress of each interactive prompt. Omit `provider` for Claude Opus 5.5; `"provider":"codex"` selects GPT-6.1 Sol when the egress serves Codex. Provider selection is durable and immutable within each SDK session: the session records its first turn's provider and the SDK's `admit_prompt` refuses another with 409; choose a new session name to switch providers. The first turn's `executor` binds the session the same way, a rule the Worker keeps itself because the SDK records no executor. `GET /health` reports supported models and the Claude authentication mode; it does not probe provider availability. Subscription requests retain the SDK's pinned wire compatibility. `npm run dev` runs the Worker under Wrangler with the remote AI binding.

Runtime measurements run the bundled Worker in local workerd (Miniflare). `scripts/local-runtime.mjs` wraps the bundle in a shim that gives the Worker and its Durable Objects an in-isolate `AI` binding: its `gateway().run()` checks that the Worker sent no provider credential, adds a stand-in gateway key and forwards the Claude request through a separate upstream Worker to the measurement's mock provider. The Worker itself has no outbound network access in these runs. Run `npm run dry-run` first.

- `node scripts/measure-local.mjs` measures initial and restored turns and receipt replay against a deterministic mock streaming provider, then restarts workerd during inference and verifies recovery, and runs Codex turns through the shim's OpenAI route against a mock that answers each turn with three `list_agents` calls before its reply. It checks that every request sets store: false, sends no `previous_response_id` and carries no provider credential, that each call replays the full history, including across turns, after Durable Object eviction and after a cancelled turn. The idle-session measurement uses Durable Object eviction; the in-flight measurement forces runtime replacement because ordinary eviction waits for active references.
- `node scripts/measure-background.mjs` holds a real SDK child in inference, replaces workerd during the child and root continuation, verifies alarm-only recovery, and cancels an interrupted root before restoration.

Turn admission submits the turn to the SDK's session log, then commits the stable UUID and watchdog before starting the resident pump through `waitUntil`. The pump reads the oldest unfinished turn, opens or reuses the runtime for its descriptor, commits the background marker before it drives a queued turn, asks the inbox to drive one turn and to settle, and schedules alarms; a turn whose cancellation was requested blocks the session's effects until the drive returns, keyed by its request ID, so a cancel reply that arrives after the drive returned cannot block the next turn. While a session has no bound provider, executor or session ID, admissions run one at a time, so of two concurrent first turns with different providers or executors the later gets 409 as it would sequentially. The pump and `warm` judge a `pending` read against the admission count taken before it, so a read answered after a later admission never marks the queue empty and the order in which WASM command replies arrive does not matter. A pump that fails drops and disposes only the runtime it was using; one that fails before it has a runtime leaves the resident runtime and its background work running. Alarms remain the independent recovery driver. The normal path reuses the already committed watchdog; recovery recommits an existing marker, or one for a running turn, before SDK initialization. Committing the marker in the pump with the descriptor it compares against, instead of at admission with differently ordered keys that the pump then rewrote, saved one statement and one row written per turn: in two alternating `measure-store.mjs` runs on 2026-10-19 against the bundle built before, the object wrote 29.4 instead of 30.4 rows per Claude turn and 80 instead of 81 per Codex turn, with workerd CPU per turn of 12.0 against 11.8 ms and 22.0–23.0 against 21.0–23.0 ms. `Accept: text/event-stream` on the owner turn POST returns a finite, request-scoped durable stream through its terminal result. Disconnecting that stream does not cancel execution. The existing GET event stream includes the full SDK tree. An `after` cursor beyond a saved terminal event returns an empty finite stream. Hot-path writes do not wait for storage confirmation one at a time. Model dispatch, model socket frames, and executor and hand frames each await `storage.sync()` first, so every earlier write, including SDK receipts, checkpoints and the admitted job, is durable before that effect leaves the session. A tool call one hand's script forwards to another hand, and its result returning to that script, skip the wait: they carry only the hands' own input and output, and the brain keeps no receipt for them. Responses and streamed events are held by Durable Object output gates until earlier writes are confirmed. A turn therefore pays one confirmation wait before its first model request instead of one per write, and a crash before confirmation loses only work that nothing outside the session has observed. In production that single wait averaged 42 ms for Claude and 52 ms for Codex turns, replacing an admission sync, a running-state sync and a sync per checkpoint and event batch before the first dispatch.

Durable Objects bill wall-clock time while an object is handling work or holding a non-hibernatable WebSocket, and SQLite bills every written row including each index entry. Keep both off idle sessions and out of the per-event path. An event-stream response keeps the session object active and billed for as long as it is open, because the object writes to it. The session socket is accepted through the hibernation API, so an idle connected client costs nothing and the object is evicted as if none were attached; prefer it for clients that stay connected. Each watcher's authority is a row in `watch_sockets` and its cursor is in the socket attachment, so events reach watchers after the object is restored. Events are one row each in the SDK's `events` table with `seq` as the plain integer primary key: no secondary index and no `AUTOINCREMENT` counter, and sessions created before that keep their table but drop its indexes. A turn's stream reads its own `first_seq`..`last_seq` range from the SDK's `turns` table, so per-turn reads scan only that primary key range. The SDK hands each logged batch to the session, which pushes it to every socket watcher whose cursor it continues and serves event streams from a tail of up to `EVENT_PAGE_SIZE` recent contiguous events holding at most `EVENT_TAIL_BYTES` of encoded events; a watcher or stream further behind pages through the SDK log. The byte bound is 4 MiB: on 2026-10-20 the 1,840 events of the platform's 60 most recent sessions had a median of 552 bytes, a 99th percentile of 1.8 KB and a maximum of 19 KB, so the tail keeps all 128 events of every measured kind, up to 32 KiB each, while a session's tail stays within a sixteenth of the 64 MiB an isolate has beside `RUNTIME_MEMORY_BUDGET_BYTES`; counted by events alone, 128 events near the 1 MiB hand frame limit kept 134 MB of heap in one session (`scripts/measure-events.mjs` in nanocode-ts). Codex raw provider frames (`api.event`) are not emitted, as in the native CLI; they were most event rows and bytes. Hands are machines that dial a session so its scripts can use them, such as the laptop where a prompt was typed. A hand is the whole machine under a name, not a workspace: `nanocode hand wss://<host>/sessions/<name>/hands` with the access token in `NANOCODE_RUNNER_TOKEN` attaches the calling machine under its host name, and `--name` or a final `/hands/<name>` path segment names it otherwise. Every session accepts hands. The socket terminates in the session Durable Object through the WebSocket Hibernation API, so an idle attached hand does not keep the object in memory or billed: each hand's registration and tool catalog are stored in `hand_sockets`, the socket carries its connection ID as an attachment, and a woken object rebuilds its hands from the open sockets before handling anything. Hands' heartbeat pings are WebSocket control frames that the runtime answers without waking the object. `GET /sessions/<name>/hands` lists attached names. A turn's `"hand"` names the machine its Code Mode scripts, and those of the subagents it starts, run on; without it scripts run on the session's configured executor, or on the only attached hand when there is no executor, and otherwise fail and list the attached hands. Inside a script any tool call runs on another attached hand when its arguments include `hand: "<name>"` (freeform tools take `{ input, hand }`), so one script can fan out across machines with `Promise.all` or read on one hand and write on another; the call travels from the script's hand through the session to the target and back, and `tools.hands()` lists the attached hands and the script's own. Selecting a hand writes the session's in-memory executor registry, so no discovery, egress lookup or connection setup sits between admission and execution. Hands attach, reconnect and leave at any time: a reconnecting hand replaces its previous socket, and a different hand process attaching under a name already attached, which its catalog's runtime ID tells apart, replaces it too and closes the older one with 1008 and the SDK's `HAND_REPLACED` reason, on which `nanocode hand` stops instead of reconnecting, so two hands started under one name no longer displace each other in a loop, killing each other's cells; the session cannot tell a live older hand from a half-open socket left by a crashed machine, so the newest hand wins; a hand whose name the session cannot use, since names are 1 to 48 lowercase letters, digits, `_` or `-` while `nanocode hand --name` also accepts capitals and longer names, is closed with 1008 and that rule as its reason, which `nanocode hand` prints before it retries, instead of an unexplained close it retried every few seconds; a turn whose hand is absent gets failed cells that dispatched nothing; a call to a hand that is not attached fails without running, so `Promise.allSettled` keeps the other hands' results; and a hand lost mid-call reports an unknown outcome without replay. Nothing waits for a hand: a client attaches its hand before prompting, normally once for its whole session, and submits as soon as the hand is listed. The hand listing includes only hands whose connection the resident SDK can use. A scope opens its runtime in Code Mode only while it has a configured executor, an attached hand or a turn naming a hand; otherwise the model gets the SDK's direct tools for subagents. A turn that changes the mode reopens the resident runtime, and hand connections pass to the new runtime, and to a runtime opened after a failure, without reconnecting, so their Code Mode state survives. Hand frames use `REMOTE_MAX_FRAME_BYTES` and `REMOTE_TIMEOUT_MS`. The SDK tells each hand the frame limit, so a script result, nested-call update or cross-hand call above it fails or drops its payload alone instead of closing the hand's socket, and Execute and Wait deadlines add the yield a script asks for to `REMOTE_TIMEOUT_MS`, while a call one hand's script makes on another hand is bounded by `REMOTE_TIMEOUT_MS` alone: a cross-hand command running longer fails as an unknown outcome and keeps running on its hand. The session's own refusals of a frame (a revoked hand, a cancelled turn, a connection that moved to a newer runtime or a failed durability wait) throw the package's `RemoteRefusal` before anything reaches the socket, and dispose a refused hand only after the refusal reaches the SDK, so the cell reports that nothing was dispatched. `scripts/worker-client.mjs --origin <url> --session <name> --hand <name>` submits once the session lists the hand; `-` as the prompt reads one prompt per stdin line and `--timing` reports per-turn connection, acceptance and first-text times.

Codex model calls within a turn, and across turns queued behind it, share one Responses WebSocket. The WASM host transport asks the session Durable Object to open it; the session checks the request's authority and upgrades through egress `/socket` without waiting for storage, because the handshake carries no session state; the durability wait happens before each frame. The session repeats that durability wait and authority check before every frame it sends. After the first call the SDK sends only new input with `previous_response_id`; a replaced socket or a restored session replays the full history. A non-101 handshake uses the safe Codex error projection: 426 moves the resident session to HTTPS at once, and other retryable rejections fall back after the SDK's retry budget. A socket closed upstream between calls is replaced before the next send. An open outbound socket keeps the session Durable Object in memory and billed, and upstream keeps an idle one for about 15 minutes, so when the session has no queued or running turn and no background work it waits `MODEL_SOCKET_LINGER_MS` and then, if it is still idle, closes its model sockets and disposes a runtime whose configured executor connection would otherwise stay open. It arms that timer only while a resident runtime holds an open model socket (the package's `connected`) or a configured executor connection, or after `warm`: a pending timer keeps the object idle but not hibernateable, which Cloudflare bills for duration (https://developers.cloudflare.com/durable-objects/concepts/durable-object-lifecycle/), and before 2026-10-20 every Claude turn and every Codex turn over HTTPS armed it with nothing to release, so each burst of turns kept its session billed for the whole linger. `node scripts/measure-idle.mjs [--turns 3] [--linger 30000] [--recovery 30000]` runs Claude and HTTPS Codex turns with production timer policies and reports the timers still pending once each turn's pump has finished, which the local shim tracks with `ctx.waitUntil` promises; on 2026-10-20 against the bundle built before, a 29,998 ms timer was pending after every turn, 3.75 GB-s of billed idle time at 128 MB, and none after the change. A turn admitted within the linger reuses the open socket and sends only its new input; one admitted later opens a new socket and replays the full history. The linger is the operator's price for that latency: 30 s keeps the object billed for at most 30 s × 128 MB = 3.75 GB-s after each burst of turns. Local measurements set it to 0. `warm` on the session socket asks the scope's resident runtime, restored from the last turn's descriptor when needed, to open its Responses socket and then starts the linger, so a client that sends it when the user starts typing moves the handshake and the runtime restore off the next turn, which reuses that socket if it arrives within the linger. While a turn is queued or running or background work is pending, `warm` uses the resident runtime as it is, because reopening it in another hands mode, after a hand attached mid-turn, stopped the running turn and repeated its model call; an idle session's `warm` reopens the runtime in the mode the next turn needs. A Claude runtime has no model socket, so `warm` only restores it. The resident runtime itself costs nothing while idle and is reused if the object stays in memory.

WASM linear memory never shrinks, and allocator fragmentation grows it well past the data it holds: a local 60-turn Claude session with a 4 MB conversation held 12.5 MB live between turns and 28 MB at its peak, while its linear memory reached 44 to 50 MB across runs. Several session objects can share one isolate and its 128 MB limit, so when a session goes idle with linear memory above `RUNTIME_MEMORY_BUDGET_BYTES` (64 MiB, half that limit) it disposes the runtime at once instead of lingering, and the next turn opens a fresh instance from storage. Retiring also drops the session's own reference to that instance: before 2026-10-19 it stayed in the map of reader instances until the next request replaced it, so a retired runtime's linear memory stayed allocated while the object idled. Reopening a 4 MB session took about 120 ms locally; with a 20 MiB budget every turn after the 28th reopened and all 60 completed. Session metrics count these as `runtime_retirements`.

Use `node scripts/summarize-timing.mjs output/<report>.json` to inspect a measurement's timing breakdown. Request results retain observed admission, runtime-open, execution and checkpoint timings. Session metrics expose the resident runtime after completion, aggregate host/WASM/bridge timings and the most recent 64 model dispatches, using the existing diagnostic retention policy. Each dispatch includes a runtime ID, dispatch ID, relative start time, header and body timings, byte counts and the egress's diagnostics, including both attempts after a 401; a Codex socket is one entry with `transport: "websocket"` and send and frame counts. SDK display events expose elapsed model-call time; event envelopes identify their host runtime and receive time. SSE adds `streamed_at` at enqueue time, before any platform output gate or network delivery. No tracing RPCs or additional durability barriers are introduced.

Elapsed times use local clocks; never subtract monotonic timestamps from different runtimes or isolates. Production Worker clocks advance only after I/O, so synchronous WASM, parsing and copy timings can be zero despite consuming CPU. Use a local V8 CPU profile for CPU attribution and keep it separate from production network measurements. Aggregate spans overlap and include the resident SDK task tree; a host operation completing during a turn may have started earlier. Turn timing records are observational and can restart at a recovery boundary. A fresh session does not prove a cold isolate, and an enqueue timestamp does not establish when the client received text.
