# Development and deployment

This is a separate Cloudflare app. Its sibling `../nanocodex` supplies the Rust SDK. `sdk-revision.json` records the SDK branch and revision containing the required activity and pending-operation APIs and portable remote output budgets; check out that revision in the sibling when preparing a fresh workspace. Keep SDK changes in that workspace and Worker-specific code here. Do not add code comments, README files, Cargo features, wasm-bindgen glue, tests, or test-only dependencies.

The WASM agent and SQLite checkpoints run inside the same session Durable Object. A stable session UUID is persisted before SDK initialization. Requests are queued durably and deduplicated by `request_id`; reusing an ID with different input returns 409. SDK ownership fences, revision checks, immutable records, model receipts, tool receipts, subagent journals, and checkpoints use the persistent store. No memory store is used for agent state.

Alarms drive work independently of client connections. A watchdog alarm is persisted before execution, using `RECOVERY_DELAY_MS` as an operator recovery policy. Completed requests return saved results. Interrupted model calls may repeat; dispatched tools retain the SDK's uncertain-outcome handling. The Worker does not promise exactly-once model billing or external side effects. Concurrent sessions use independent Durable Objects. Each session executes queued root turns serially, while SDK subagents can run concurrently. Durable background markers keep alarms armed after root requests finish until the SDK task tree, continuation turns, journal writes, and detached remote execution are quiescent. Resume pending SDK operations in accepted order before later requests. Cancellation must settle in the SDK before the queue reports it complete. The `subagent-completion:` request-ID prefix is reserved.

Use two deployments. The public `nanocode-worker` owns session Durable Objects and Connect ingress. The private `nanocode-egress` owns the account authority, credential vault, provider transports, connector transports, and authentication for execution hosts. The public deployment must have no provider credentials, vault key, account namespace binding, or credential-returning interface. Named entrypoints share the private deployment. The agent's only outbound network capability is a trusted host adapter to those bindings; agent-selected account IDs, headers, and URLs do not confer authority.

`AccountAuthority` owns rotating subscription credentials, Connect grants and token families, selected connections, app/origin/principal bindings, and thread routing. It serializes refreshes, commits an uncertain-exchange marker before contacting the token endpoint, and persists rotated credentials before releasing access material inside private egress. An uncertain refresh requires importing a fresh credential document. Credentials stay in Cloudflare secrets and encrypted Durable Object storage. A Container is not required for authentication or inference. Worker secrets and access tokens must never appear in source, command arguments, logs, or benchmark reports. The retired `SubscriptionAuth` class remains exported to retain its namespace without deleting existing storage; it no longer serves credentials.

Cloudflare chooses physical Durable Object placement. Agent execution and checkpoint storage are co-located by construction; this does not pin all objects or the account authority to an exact Cloudflare colo. SQLite access stays inside each session, including the full SDK subagent tree. Reuse the resident WASM instance and SDK session across turns; status and event history must not initialize WASM. Root turns are serial, while SDK children can run concurrently. Connect grants use separate SDK session identities inside the same thread DO. Fresh grants must not inherit previous grant transcripts or outputs.

The default tool collection omits local machine tools and enables SDK delegation. Shell, filesystem, desktop, and remote Code Mode execution require a separately configured execution host; this app does not create a machine environment. Use the SDK RemoteFrame/RemoteOperation protocol for that host, with orchestration and tool receipts remaining in the brain. A machine executor's unrestricted network access is governed by that host; the Worker cannot enforce a proxy for an independently configured machine.

Every external Connect operation has a live account authorization check. Connector calls check canonical authority even when an access credential is cached. Revocation also writes durable session fences and retries delivery through an account outbox. Acknowledgment means the fence is durable, and already-dispatched external effects cannot be recalled. Generic vault operations return only status; arbitrary response-body redaction is not a credential boundary. Cache lifetimes, token lifetimes, recovery delay, event page size, stream revalidation, and execution-host frame and timeout policies are explicit Wrangler variables.

Install Rust 1.97 or newer, the `wasm32-unknown-unknown` target, and Node.js. Run `npm ci`, `cargo check --locked --lib --target wasm32-unknown-unknown`, `npm run check`, and `npm run dry-run`. Run SDK checks from `../nanocodex` with `cargo check --locked --lib` and `cargo check --locked --lib --target wasm32-unknown-unknown`. Local compilation keeps incremental artifacts without debug information. The optimized WASM build uses the `wasm` profile. Dependency resolution is pinned by both lockfiles.

Deploy from this directory:

For interactive login, use the existing Brave Browser profile through the installed CUA provider recorded in `~/.nanocodex/runtimes/openai-cua/provider.json`. That provider owns the working native application connection. A fresh Chrome profile does not share the user's saved login or browser session. Unlock 1Password through its normal UI when the saved credential requires it.

1. Run `npx wrangler login`, or provide `CLOUDFLARE_API_TOKEN` through your secret manager.
2. Run `npm run dry-run` to review both deployment bundles, then `npm run deploy` when deployment is authorized. For a migration from the previous single-Worker deployment, first import a fresh dedicated credential into private egress and remove any old public `OAUTH_JSON`, `ANTHROPIC_API_KEY`, `CONNECTIONS_JSON`, `VAULT_KEY`, or `RUNNER_TOKEN` secrets with Wrangler. Wrangler retains existing secrets across deployments.
3. Set the public API access token with `npx wrangler secret put WORKER_TOKEN --config wrangler.jsonc`.
4. Run `node scripts/import-oauth.mjs /absolute/path/to/oauth.json`. Omitting the path reads the default Claude Code credential from the macOS keychain. The importer accepts Anthropic entries from Pi/OMP-style documents and Claude Code's `claudeAiOauth` document, and pipes only the normalized Claude credential into `wrangler secret put OAUTH_JSON`. It does not write a credential file.

For Codex subscriptions, create a dedicated login with `CODEX_HOME=/absolute/private/directory codex login`, then run `node scripts/import-codex-oauth.mjs /absolute/private/directory/auth.json`. The importer pipes the document only into private `CODEX_OAUTH_JSON`; that deployment then owns its rotating refresh credential. For a dedicated Claude Code login, set `CLAUDE_CONFIG_DIR` when logging in and importing to select its scoped keychain entry. Do not run inference clients against either dedicated credential after import.

For API-key authentication instead, set `ANTHROPIC_API_KEY` with `wrangler secret put --config wrangler.egress.jsonc` and omit `OAUTH_JSON`; set public `MODEL_AUTH` to `api_key`. Subscription authentication takes precedence when both are configured. Do not run the same rotating refresh credential independently in multiple deployments or local clients; use a dedicated login when independent refresh ownership is needed. Uploading a fresh credential document changes the seed digest and resets the account's retained credential state. `ANTHROPIC_ENDPOINT` belongs only to private egress and is an operator-approved upstream transport override.

Owner API requests require `Authorization: Bearer $WORKER_TOKEN`. Submit `POST /sessions/<name>/turns` with JSON `{"request_id":"job-1","prompt":"Your instruction","provider":"claude"}`; the response is 202 while queued or running. Poll `GET /sessions/<name>/turns/job-1` for the final result. Repeating the POST with the same input returns the saved result after completion. Cancel with `POST /sessions/<name>/turns/job-1/cancel`. Read bounded event pages at `GET /sessions/<name>/events?after=0&limit=128` and process counters at `GET /sessions/<name>/metrics`. Omit `provider` for Claude Opus 5.5, or use `"provider":"codex"` for GPT-6.1 Sol. Provider selection is durable and immutable within each SDK session; choose a new session name to switch providers. `GET /health` reports supported models and the Claude authentication mode; it does not probe provider availability. Subscription requests retain the SDK's pinned wire compatibility. Run `npm run dev` for both deployments in one local workerd session.

For an execution host, set private `RUNNER_URL` and the private `RUNNER_TOKEN` secret, and set public `RUNNER_ENABLED` to `true`. Use the SDK runner listener with `--multi-session`, an explicit `--workspace`, frame-size and timeout policy. Without `--multi-session`, the SDK example accepts one connection and exits on disconnect. The Worker reconnects only by replacing a failed runtime at a later recovery boundary, and does not replay an uncertain dispatched command. Connect grants must explicitly select the `runner` connection.

Runtime measurements:

- `npm run dry-run && node scripts/measure-local.mjs` runs the compiled WASM in local workerd against a deterministic mock streaming provider, measures initial and restored turns and receipt replay, then restarts workerd during inference and verifies recovery. The idle-session measurement uses Durable Object eviction; the in-flight measurement forces runtime replacement because ordinary eviction waits for active references.
- Add `--transport` to the local measurement for stalled response headers, idle streams, stalled error projection, cancellation, long active streams, and SDK queue progress after transport timeouts. Add it to `measure-authority.mjs` to include a stalled model dispatch after a401-triggered credential refresh.
- `node scripts/measure-local.mjs --live` requires `OAUTH_FILE` containing a dedicated subscription login or `ANTHROPIC_API_KEY` in the environment. It measures short Opus 5.5 requests, including session restoration after eviction. Reports contain only the fixed measurement prompt's response and safe counters.
- `node scripts/measure-background.mjs` holds a real SDK child in inference, replaces workerd during the child and root continuation, verifies alarm-only recovery, and cancels an interrupted root before restoration.
- `node scripts/measure-authority.mjs` measures coalesced rotating refreshes, zero-authority-RPC warm model dispatch, encrypted rotation, and fail-closed recovery after runtime replacement during refresh.
- `node scripts/measure-capabilities.mjs` invokes the actual WASM SDK catalog, connector and vault tools, verifies credential injection and safe projections, and checks model input and persisted receipts for credential exposure.
- `node scripts/measure-connect.mjs` exercises PKCE, origin and grant isolation, hosted turns and durable events, service-only connector/vault calls, refresh reuse and revocation.
- `node scripts/measure-remote.mjs` builds the SDK runner and exercises the actual remote Code Mode protocol against a separate native execution host, including workspace edits, Bash, persisted code cells, callbacks, cancellation of unfinished cells at turn completion, and uncertain disconnects. Its loopback transport measurement is not a production networking benchmark.
- `node scripts/measure-wrangler.mjs` runs both deployments through Wrangler, verifies TypeScript hot reload without rewriting WASM, and replaces Wrangler during inference to check autonomous disk-backed recovery. It temporarily edits and restores a health response field; run it while the Worker source is idle.
- `node scripts/benchmark-transfer.mjs 65536 256` compares JSON byte-array round trips with the raw memory copy used by the WASM HTTP body bridge for 16 MiB of data. This isolates serialization cost, not inference throughput or full application speed. Chunk size and count are benchmark inputs.

For isolated SDK verification, `NANOCODE_WASM_PATH` selects the compiled WASM used by Miniflare measurements and `NANOCODE_SDK_PATH` selects the SDK workspace used by the remote measurement. `CARGO_TARGET_DIR`, when set, selects its runner build and executable directory. These overrides do not change deployment configuration.

Keep all reports and generated bundles in ignored `output/`, `dist/`, and `target/`. Local workerd latency does not establish production colo latency. First-time optimized builds, cached builds, mock-provider overhead, and live model latency are separate measurements.

Turn admission commits the queue entry, background marker, stable UUID, and watchdog before starting the resident pump through `waitUntil`. Alarms remain the independent recovery driver. The normal path reuses the already committed watchdog and marker; recovery recommits them before SDK initialization. `Accept: text/event-stream` on the owner turn POST returns a finite, request-scoped durable stream through its terminal result. Disconnecting that stream does not cancel execution. The existing GET event stream includes the full SDK tree. An `after` cursor beyond a saved terminal event returns an empty finite stream.

Select an execution host with `"executor":"paradigm-a"` or another configured ID on a turn, including Connect REST and MCP submissions. Provider and executor selection are immutable within each SDK scope; omission on subsequent turns retains the selection. Private `RUNNERS_JSON` is an array of `{id,url,token,binding?}`. Canonical Connect grants must select `runner:<id>`; legacy `runner` selects only the default executor. The private account authority checks executor ownership and live grants before connecting. Optional `RUNNER_VPC_*` bindings route through fixed private VPC services. Agent input never selects a transport URL, binding, or credential. `SESSION_LOCATION_HINT` is an operator placement hint for newly created session DOs, currently eastern North America near Paradigm; it neither relocates existing objects nor guarantees a specific colo.

The Paradigm deployment uses two isolated executor users and workspaces on one physical Linux host. Build the pinned SDK runner with `cargo build --locked --release -p nanocode --example runner`. Install it as `/usr/local/libexec/nanocode-runner`, install `scripts/runner-launcher.py` alongside it as `nanocode-runner-launcher.py`, and use the units in `deploy/`. Instance `a` uses user `nanocode-a`, workspace `/var/lib/nanocode-worker/a/workspace`, and protected `/etc/nanocode-worker/runner-a.env` containing `NANOCODE_RUNNER_TOKEN` and `NANOCODE_RUNNER_PORT`; instance `b` uses separate equivalents. The launcher removes the credential from the inherited environment and supplies it through stdin. Linux multi-session mode disables process dumpability before reading the credential; keep the launcher's environment file root-owned and inaccessible to execution users. Each authenticated connection gets its own evaluator, while connections to an executor share its operator workspace. Systemd owns restart and boot recovery. Install a root-owned Rust 1.97 toolchain at `/opt/nanocode/toolchain`; the unit includes its `bin` directory in PATH and keeps it read-only to executors. This makes Cargo available despite `ProtectHome`, while build output and Cargo caches stay in the execution user's writable directories. The named Cloudflare tunnel has no public ingress and runs under a third user whose credential file is inaccessible to both executors.

Private `CODEX_TRANSPORT`, when bound, sends the fixed HTTPS Codex endpoint through the named tunnel with full upstream certificate verification. Provider credentials remain owned and stored by private egress and are injected there; the tunnel carries the request transiently under a separate Linux user. Execution hosts receive no provider credential configuration. This operator transport addresses the observed fast HTML 403s on direct Worker egress; User-Agent and routing-identity experiments did not fix them. `GET /metrics?probe=codex` performs an owner-authorized handshake-only probe, with no inference payload. Model diagnostics contain only fixed enums, status, timings, and header-presence booleans; session metrics retain correlated recent diagnostics in memory and filter them by SDK scope.

Private `MODEL_RESPONSE_HEADERS_TIMEOUT_MS` and `MODEL_STREAM_IDLE_TIMEOUT_MS` bound each model fetch attempt and each pending body read, including the second attempt after a 401 and error-body projection. Both default to 120000ms. The header timer ends when headers arrive; active streams have no total-duration limit. Idle time while a downstream consumer applies backpressure is not counted. A timeout aborts that transport attempt and reports a fixed safe failure through the SDK; it does not replay prior tools or establish that the provider did not accept or bill the request. Alarms remain recovery wakeups rather than wall-clock model deadlines.

Run `WORKER_TOKEN` through your secret manager's environment injection and execute `node scripts/measure-curl.mjs --provider claude --samples 6` or the Codex equivalent. Add `--executor paradigm-a --tools` to measure real remote Bash, workspace edits, Code Mode store/load, concurrent tool calls, and brain callbacks. Credentials enter curl through stdin configuration and never command arguments. TTFT starts immediately before spawning curl and ends at the first nonempty assistant text delta; HTTP headers and keepalives do not count. Tool workflows may emit their first text before or after tools, so compare completion and event timings as well. Measurements retain only synthetic workflow timing, success flags, event types, and safe counters in ignored `output/`.

Add `--reasoning` for the fixed arithmetic prompt and use `node scripts/summarize-timing.mjs output/<report>.json` to inspect the breakdown. Request results retain observed admission, runtime-open, execution and checkpoint timings. Session metrics expose the resident runtime after completion, aggregate host/WASM/bridge timings and the most recent 64 model dispatches, using the existing diagnostic retention policy. Each dispatch includes a runtime ID, dispatch ID, relative start time, header and body timings, byte counts and safe private-egress diagnostics, including both attempts after a 401. SDK display events expose elapsed model-call time; event envelopes identify their host runtime and receive time. SSE adds `streamed_at` at enqueue time, before any platform output gate or network delivery. No tracing RPCs or additional durability barriers are introduced.

Elapsed times use local clocks; never subtract monotonic timestamps from different runtimes or isolates. Production Worker clocks advance only after I/O, so synchronous WASM, parsing and copy timings can be zero despite consuming CPU. Use a local V8 CPU profile for CPU attribution and keep it separate from production network measurements. Aggregate spans overlap and include the resident SDK task tree; a host operation completing during a turn may have started earlier. Turn timing records are observational and can restart at a recovery boundary. A fresh session does not prove a cold isolate, and an enqueue timestamp does not establish when the client received text.
