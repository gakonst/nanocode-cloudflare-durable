# Development and deployment

This is a separate Cloudflare app. Its sibling `../nanocodex` supplies the Rust SDK. `sdk-revision.json` records the SDK master revision the Worker builds against, including the activity and pending-operation APIs, portable remote output budgets and the hand executor registry; check out that revision in the sibling when preparing a fresh workspace. Keep SDK changes in that workspace and Worker-specific code here. Do not add code comments, README files, Cargo features, wasm-bindgen glue, tests, or test-only dependencies.

The WASM agent and SQLite checkpoints run inside the same session Durable Object. A stable session UUID is persisted before SDK initialization. Requests are queued durably and deduplicated by `request_id`; reusing an ID with different input returns 409. SDK ownership fences, revision checks, immutable records, model receipts, tool receipts, subagent journals, and checkpoints use the persistent store. No memory store is used for agent state.

Alarms drive work independently of client connections. A watchdog alarm is persisted before execution, using `RECOVERY_DELAY_MS` as an operator recovery policy. Completed requests return saved results. Interrupted model calls may repeat; dispatched tools retain the SDK's uncertain-outcome handling. The Worker does not promise exactly-once model billing or external side effects. Concurrent sessions use independent Durable Objects. Each session executes queued root turns serially, while SDK subagents can run concurrently. Durable background markers keep alarms armed after root requests finish until the SDK task tree, continuation turns, journal writes, and detached remote execution are quiescent. Resume pending SDK operations in accepted order before later requests. Cancellation must settle in the SDK before the queue reports it complete. The `subagent-completion:` request-ID prefix is reserved.

Use two deployments. The public `nanocode-worker` owns session Durable Objects and Connect ingress. The private `nanocode-egress` owns the account authority, credential vault, provider transports, connector transports, and authentication for execution hosts. The public deployment must have no provider credentials, vault key, account namespace binding, or credential-returning interface. Named entrypoints share the private deployment. The agent's only outbound network capability is a trusted host adapter to those bindings; agent-selected account IDs, headers, and URLs do not confer authority.

`AccountAuthority` owns rotating subscription credentials, Connect grants and token families, selected connections, app/origin/principal bindings, and thread routing. It serializes refreshes, commits an uncertain-exchange marker before contacting the token endpoint, and persists rotated credentials before releasing access material inside private egress. An uncertain refresh requires importing a fresh credential document. Credentials stay in Cloudflare secrets and encrypted Durable Object storage. A Container is not required for authentication or inference. Worker secrets and access tokens must never appear in source, command arguments, logs, or benchmark reports. The retired `SubscriptionAuth` class remains exported to retain its namespace without deleting existing storage; it no longer serves credentials.

Cloudflare chooses physical Durable Object placement. Agent execution and checkpoint storage are co-located by construction; this does not pin all objects or the account authority to an exact Cloudflare colo. SQLite access stays inside each session, including the full SDK subagent tree. Reuse the resident WASM instance and SDK session across turns; status and event history must not initialize WASM. Root turns are serial, while SDK children can run concurrently. Connect grants use separate SDK session identities inside the same thread DO. Fresh grants must not inherit previous grant transcripts or outputs.

The default tool collection omits local machine tools and enables SDK delegation. Shell, filesystem, desktop, and remote Code Mode execution require a separately configured execution host; this app does not create a machine environment. Use the SDK RemoteFrame/RemoteOperation protocol for that host, with orchestration and tool receipts remaining in the brain. A machine executor's unrestricted network access is governed by that host; the Worker cannot enforce a proxy for an independently configured machine.

Every external Connect operation has a live account authorization check. Connector calls check canonical authority even when an access credential is cached. Revocation also writes durable session fences and retries delivery through an account outbox. Acknowledgment means the fence is durable, and already-dispatched external effects cannot be recalled. Generic vault operations return only status; arbitrary response-body redaction is not a credential boundary. Cache lifetimes, token lifetimes, recovery delay, event page size, stream revalidation, and execution-host frame and timeout policies are explicit Wrangler variables.

Install Rust 1.97 or newer, the `wasm32-unknown-unknown` target, and Node.js. Run `npm ci`, `cargo check --locked --lib --target wasm32-unknown-unknown`, `npm run check`, and `npm run dry-run`. Run SDK checks from `../nanocodex` with `cargo check --locked --lib` and `cargo check --locked --lib --target wasm32-unknown-unknown`. Local compilation keeps incremental artifacts without debug information. The optimized WASM build uses the `wasm` profile. Dependency resolution is pinned by both lockfiles.

Deploy from this directory:

For interactive login, use the existing Brave Browser profile through the installed CUA provider recorded in `~/.nanocodex/runtimes/openai-cua/provider.json`. That provider owns the working native application connection. A fresh Chrome profile does not share the user's saved login or browser session. Unlock 1Password through its normal UI when the saved credential requires it.

1. Run `npx wrangler login`, or provide `CLOUDFLARE_API_TOKEN` through your secret manager.
2. Run `npm run dry-run` to review both deployment bundles, then `npm run deploy` when deployment is authorized. For a migration from the previous single-Worker deployment, first import a fresh dedicated credential into private egress and remove any old public `OAUTH_JSON`, `ANTHROPIC_API_KEY`, `CONNECTIONS_JSON`, `VAULT_KEY`, or `RUNNER_TOKEN` secrets with Wrangler. Wrangler retains existing secrets across deployments.
3. Set the public API access token with `npx wrangler secret put WORKER_TOKEN --config wrangler.jsonc`.
4. Run `node scripts/import-oauth.mjs /absolute/path/to/oauth.json`. Omitting the path reads the default Claude Code credential from the macOS keychain. The importer accepts Anthropic entries from Pi/OMP-style documents and Claude Code's `claudeAiOauth` document, and pipes only the normalized Claude credential into `wrangler secret put OAUTH_JSON`. It does not write a credential file.

For Codex subscriptions, create a dedicated login with `CODEX_HOME=/absolute/private/directory codex login`, then run `node scripts/import-codex-oauth.mjs /absolute/private/directory/auth.json`. The importer pipes the document only into private `CODEX_OAUTH_JSON`; that deployment then owns its rotating refresh credential. For a dedicated Claude Code login, set `CLAUDE_CONFIG_DIR` when logging in and importing to select its scoped keychain entry. Do not run inference clients against either dedicated credential after import.

For API-key authentication instead, set `ANTHROPIC_API_KEY` with `wrangler secret put --config wrangler.egress.jsonc` and omit `OAUTH_JSON`; set public `MODEL_AUTH` to `api_key`. Subscription authentication takes precedence when both are configured. Do not run the same rotating refresh credential independently in multiple deployments or local clients; use a dedicated login when independent refresh ownership is needed. Uploading a fresh credential document changes the seed digest and resets the account's retained credential state. `ANTHROPIC_ENDPOINT` belongs only to private egress and is an operator-approved upstream transport override.

Owner API requests require `Authorization: Bearer $WORKER_TOKEN`. Submit `POST /sessions/<name>/turns` with JSON `{"request_id":"job-1","prompt":"Your instruction","provider":"claude"}`; the response is 202 while queued or running. Poll `GET /sessions/<name>/turns/job-1` for the final result. Repeating the POST with the same input returns the saved result after completion. Cancel with `POST /sessions/<name>/turns/job-1/cancel`. Read bounded event pages at `GET /sessions/<name>/events?after=0&limit=128` and process counters at `GET /sessions/<name>/metrics`. Omit `provider` for Claude Opus 5.5, or use `"provider":"codex"` for GPT-6.1 Sol. Provider selection is durable and immutable within each SDK session; choose a new session name to switch providers. `GET /health` reports supported models and the Claude authentication mode; it does not probe provider availability. Subscription requests retain the SDK's pinned wire compatibility. Run `npm run dev` for both deployments in one local workerd session.

For an execution host, set private `RUNNER_URL` and the private `RUNNER_TOKEN` secret, and set public `RUNNER_ENABLED` to `true`. Use the SDK runner listener with `--multi-session`, an explicit `--workspace`, frame-size and timeout policy. Without `--multi-session`, the SDK example accepts one connection and exits on disconnect. The Worker reconnects only by replacing a failed runtime at a later recovery boundary, and does not replay an uncertain dispatched command. Connect grants must explicitly select the `runner` connection.

These overrides do not change deployment configuration.

Keep all reports and generated bundles in ignored `output/`, `dist/`, and `target/`. Local workerd latency does not establish production colo latency. First-time optimized builds, cached builds, mock-provider overhead, and live model latency are separate measurements.

Turn admission commits the queue entry, background marker, stable UUID, and watchdog before starting the resident pump through `waitUntil`. Alarms remain the independent recovery driver. The normal path reuses the already committed watchdog and marker; recovery recommits them before SDK initialization. `Accept: text/event-stream` on the owner turn POST returns a finite, request-scoped durable stream through its terminal result. Disconnecting that stream does not cancel execution. The existing GET event stream includes the full SDK tree. An `after` cursor beyond a saved terminal event returns an empty finite stream.

Hot-path writes do not wait for storage confirmation one at a time. Model dispatch, Codex socket frames, executor and hand frames, and connector or vault calls each await `storage.sync()` first, so every earlier write, including SDK receipts, checkpoints and the admitted job, is durable before that effect leaves the session. A tool call one hand's script forwards to another hand, and its result returning to that script, skip the wait: they carry only the hands' own input and output, and the brain keeps no receipt for them. Responses and streamed events are held by Durable Object output gates until earlier writes are confirmed. A turn therefore pays one confirmation wait before its first model request instead of one per write, and a crash before confirmation loses only work that nothing outside the session has observed. In production that single wait averaged 42 ms for Claude and 52 ms for Codex turns, replacing an admission sync, a running-state sync and a sync per checkpoint and event batch before the first dispatch.

Durable Objects bill wall-clock time while an object is handling work or holding a non-hibernatable WebSocket, and SQLite bills every written row including each index entry. Keep both off idle sessions and out of the per-event path. Events are one row each with `seq` as the plain integer primary key: no secondary index and no `AUTOINCREMENT` counter, and sessions created before that keep their table but drop its indexes. Turn streams start from the job's recorded `first_seq` and finished turns record `last_seq`, so per-turn reads scan the primary key from the turn's own events. Codex raw provider frames (`api.event`) are not emitted, as in the native CLI; they were most event rows and bytes. The WASM event pump sends the first event after a quiet period at once and then at most one batch per `EVENT_COALESCE_MS`, an operator policy for how often a streaming client sees new text (100 ms, ten updates a second), and merges consecutive assistant and reasoning-summary deltas of the same item into one event. A turn that waits for its events to drain flushes immediately, so coalescing never delays a result. Model request bodies and Codex socket frames cross from WASM as raw bytes through the `dispatch_body` import, and the session forwards a model body to private egress unchanged with its routing in the `x-nanocode-model` header, so a large request is not JSON-escaped and parsed again on the way out. `node scripts/measure-cost.mjs --bin <nanocode>` runs Codex, Claude and Codex-with-laptop-hand sessions against the deployment, three short turns each and then 90 s idle, and reads each session's active time, CPU, rows and WebSocket messages from the Cloudflare GraphQL API with `WORKER_TOKEN`, `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` in the environment; `--analyze <report>` retries the analytics for a saved run. Before these changes the Codex sessions stayed active for about 900 s after three turns, until upstream closed their idle sockets, and wrote 425 and 955 rows; afterwards the same runs were active 8.8 s and 15 s, including 90 s with the hand attached, and wrote 157 and 224 rows. Claude sessions were active about 5 s either way and went from 232 to 143 rows. The Codex turns that follow an idle period took 0.5 to 0.9 s longer for the new socket and full replay. Event coalescing then halved rows written per turn in a local 20-turn run with 40 text deltas per reply, from 81.6 to 42.9, and cut bridge event calls from 945 to 89. A CPU profile of a 110-turn local session with 200 deltas per reply (`INSPECT=<port>` in a profiling harness with an unstripped build) found software SHA-256 in 38% of samples; with the SDK's BLAKE3 record keys WASM CPU per turn fell from 173.5 ms to 20.7 ms and storage from 19.1 MB to 12.1 MB. Session metrics report `database_bytes`, the object ID for analytics, and the resident runtime's `wasm_memory_bytes`. The `wasm` profile uses `opt-level = "s"`: on the same 110-turn run, two runs each measured WASM CPU per turn at 24.0 and 30.5 ms with `"z"` (7.39 MB, 2.31 MB gzipped), 19.1 and 17.8 ms with `"s"` (8.01 MB, 2.48 MB) and 8.4 and 18.7 ms with `3` (10.51 MB, 3.39 MB); `"s"` keeps most of the CPU saving without the larger module every cold start of a hibernated session compiles.

Select an execution host with `"executor":"paradigm-a"` or another configured ID on a turn, including Connect REST and MCP submissions. Provider and executor selection are immutable within each SDK scope; omission on subsequent turns retains the selection. Private `RUNNERS_JSON` is an array of `{id,url,token,binding?}`. Canonical Connect grants must select `runner:<id>`; legacy `runner` selects only the default executor. Private egress checks owner executor selection against its local registry without a broker RPC; grant-scoped connections still require live account authority checks before connecting. Optional `RUNNER_VPC_*` bindings route through fixed private VPC services. Agent input never selects a transport URL, binding, or credential. `SESSION_LOCATION_HINT` is an operator placement hint for newly created session DOs, currently eastern North America near Paradigm; it neither relocates existing objects nor guarantees a specific colo.

Hands are machines that dial a session so its scripts can use them, such as the laptop where a prompt was typed. A hand is the whole machine under a name, not a workspace: `nanocode hand wss://<host>/sessions/<name>/hands` with the owner token in `NANOCODE_RUNNER_TOKEN` attaches the calling machine under its host name, and `--name` or a final `/hands/<name>` path segment names it otherwise. Connect grants must select `runner:<name>`. Every session accepts hands. The socket terminates in the session Durable Object through the WebSocket Hibernation API, so an idle attached hand does not keep the object in memory or billed: each hand's registration and tool catalog are stored in `hand_sockets`, the socket carries its connection ID as an attachment, and a woken object rebuilds its hands from the open sockets before handling anything. Hands' heartbeat pings are WebSocket control frames that the runtime answers without waking the object. `GET /sessions/<name>/hands` lists attached names. A turn's `"hand"` names the machine its Code Mode scripts, and those of the subagents it starts, run on; without it scripts run on the session's configured executor, or on the only attached hand when there is no executor, and otherwise fail and list the attached hands. Inside a script any tool call runs on another attached hand when its arguments include `hand: "<name>"` (freeform tools take `{ input, hand }`), so one script can fan out across machines with `Promise.all` or read on one hand and write on another; the call travels from the script's hand through the session to the target and back, and `tools.hands()` lists the attached hands and the script's own. Selecting a hand writes the session's in-memory executor registry, so no discovery, egress lookup or connection setup sits between admission and execution. Hands attach, reconnect and leave at any time: a reconnecting hand replaces its previous socket; a turn whose hand is absent gets failed cells that dispatched nothing; a call to a hand that is not attached fails without running, so `Promise.allSettled` keeps the other hands' results; and a hand lost mid-call reports an unknown outcome without replay. Nothing waits for a hand: a client attaches its hand before prompting, normally once for its whole session, and submits as soon as the hand is listed. The hand listing includes only hands whose connection the resident SDK can use. A scope opens its runtime in Code Mode only while it has a configured executor, an attached hand or a turn naming a hand; otherwise the model gets the SDK's direct tools for subagents, connectors and the vault. A turn that changes the mode reopens the resident runtime, and hand connections pass to the new runtime, and to a runtime opened after a failure, without reconnecting, so their Code Mode state survives; revocation still closes them. Hand frames use `REMOTE_MAX_FRAME_BYTES` and `REMOTE_TIMEOUT_MS`. `scripts/try-worker.sh <provider> here` attaches the calling machine as the hand for its own prompt. It runs `scripts/worker-client.mjs`, which opens one HTTP/2 connection while the hand dials, submits once the session lists the hand, and carries every turn and event stream of the session over that connection; `-` as the prompt reads one prompt per stdin line and `--timing` reports per-turn connection, response-header and first-text times.

`node scripts/measure-hands.mjs` builds `nanocode` from the sibling SDK, attaches `nanocode hand` processes to local workerd with the mock provider, and checks that a turn without hands or an executor gets direct tools, one script fanning out to both hands with `Promise.all`, a script writing a file on its own hand and copying it to the other with `apply_patch`, per-turn hand choice, a turn without `hand` failing among two hands and running on the only one, `Promise.allSettled` after one hand is killed, reattachment, brain callbacks and Code Mode state on a hand, a departed hand failing its cell at once, a 45 s idle connection (`HANDS_KEEPALIVE_MS`) staying attached on workerd's ping replies, and both hands staying listed and usable without reconnecting after the session object is evicted. On an Apple Silicon laptop two hands attached 537 ms after process spawn, two concurrent 1 s `exec_command` calls on different hands spanned 1068 ms from first start to last end inside one script, the cross-hand copy turn took 74 ms, a killed hand left the registry within 3 ms, and single-exec turns took 34 ms median from submission to completion. Against production, a hand on the Paradigm Linux host ran cells with a nested shell command in about 90 ms on the session clock, while a laptop on a link with about 640 ms round-trip time took 0.9–1.7 s per cell; the link, not the hand protocol, sets that cost.

`node scripts/measure-hands-deployed.mjs --provider codex --session <new name> --bin <nanocode> --spawn linux --expect laptop` runs the same flow against a deployment with `WORKER_TOKEN` in the environment. It spawns and later kills one hand itself and expects the others to be attached already, then runs fixed scripts from each hand: calls to every hand by name and without one, a `Promise.all` fan-out of 1 s commands, a file written on the script's hand and another on a second hand, `Promise.allSettled` across attached, departed and unknown hands, a turn whose hand has left and a turn after the hand returns. The report in `output/` keeps the per-call timings and session metrics. Claude can refuse these verbatim benchmark prompts; Codex runs them. With a Linux host hand near the session (26 ms brain round trip) and a laptop hand (94 ms), calls naming the script's own hand ran locally in 4–6 ms on Linux and 10–69 ms on the laptop, whose load average was above 28 from other builds, calls to the other hand took 128–166 ms in either direction, a fan-out of two 1 s commands finished in 1.19–1.56 s, calls to departed or unknown hands failed immediately, and hand frame sends averaged 8.5 ms with a 46 ms maximum. Before hands learned their registered names and forwarded calls skipped the storage wait, self-named calls took 45–263 ms and frame sends averaged 24 ms with a 542 ms maximum.

The Paradigm deployment uses two isolated executor users and workspaces on one physical Linux host. Build the pinned SDK runner with `cargo build --locked --release -p nanocode --example runner`. Install it as `/usr/local/libexec/nanocode-runner`, install `scripts/runner-launcher.py` alongside it as `nanocode-runner-launcher.py`, and use the units in `deploy/`. Instance `a` uses user `nanocode-a`, workspace `/var/lib/nanocode-worker/a/workspace`, and protected `/etc/nanocode-worker/runner-a.env` containing `NANOCODE_RUNNER_TOKEN` and `NANOCODE_RUNNER_PORT`; instance `b` uses separate equivalents. The launcher removes the credential from the inherited environment and supplies it through stdin. Linux multi-session mode disables process dumpability before reading the credential; keep the launcher's environment file root-owned and inaccessible to execution users. Each authenticated connection gets its own evaluator, while connections to an executor share its operator workspace. Systemd owns restart and boot recovery. Install a root-owned Rust 1.97 toolchain at `/opt/nanocode/toolchain`; the unit includes its `bin` directory in PATH and keeps it read-only to executors. This makes Cargo available despite `ProtectHome`, while build output and Cargo caches stay in the execution user's writable directories. The named Cloudflare tunnel has no public ingress and runs under a third user whose credential file is inaccessible to both executors.

Private `CODEX_TRANSPORT`, when bound, sends the fixed HTTPS Codex endpoint through the named tunnel with full upstream certificate verification. Provider credentials remain owned and stored by private egress and are injected there; the tunnel carries the request transiently under a separate Linux user. Execution hosts receive no provider credential configuration. This operator transport addresses the observed fast HTML 403s on direct Worker egress; User-Agent and routing-identity experiments did not fix them. `GET /metrics?probe=codex` performs an owner-authorized handshake-only probe, with no inference payload. Model diagnostics contain only fixed enums, status, timings, and header-presence booleans; session metrics retain correlated recent diagnostics in memory and filter them by SDK scope.

Codex model calls within a turn, and across turns queued behind it, share one Responses WebSocket. The WASM host transport asks the session Durable Object to open it; the session checks the request's authority and fences and upgrades through private egress `/socket` without waiting for storage, because the handshake carries no session state; the durability wait happens before each frame. Egress validates the session like model dispatch, accepts only Codex, injects the Codex credential into the handshake, sends it through `CODEX_TRANSPORT` when bound, refreshes once after a 401, and returns the upstream socket with only allowlisted response headers, so credentials never reach the session or WASM. The session repeats that durability wait and authority check before every frame it sends. After the first call the SDK sends only new input with `previous_response_id`; a replaced socket or a restored session replays the full history. A non-101 handshake uses the safe Codex error projection: 426 moves the resident session to HTTPS at once, and other retryable rejections fall back after the SDK's retry budget. A socket closed upstream between calls is replaced before the next send. Each pending socket read is bounded by private `MODEL_STREAM_IDLE_TIMEOUT_MS`; at the deadline the session closes the socket and the SDK retries on a new one. An open outbound socket keeps the session Durable Object in memory and billed, and upstream keeps an idle one for about 15 minutes, so when the session has no queued or running turn and no background work it waits `MODEL_SOCKET_LINGER_MS` and then, if it is still idle, closes its model sockets and disposes a runtime whose configured executor connection would otherwise stay open. A turn admitted within the linger reuses the open socket and sends only its new input; one admitted later opens a new socket, which costs about 0.6 to 1.3 s through `CODEX_TRANSPORT`, and replays the full history. The linger is the operator's price for that latency: 30 s keeps the object billed for at most 30 s × 128 MB = 3.75 GB-s after each burst of turns. Local measurements set it to 0. The resident runtime itself costs nothing while idle and is reused if the object stays in memory.

WASM linear memory never shrinks, and allocator fragmentation grows it well past the data it holds: a local 60-turn Claude session with a 4 MB conversation held 12.5 MB live between turns and 28 MB at its peak, while its linear memory reached 44 to 50 MB across runs. Several session objects can share one isolate and its 128 MB limit, so when a session goes idle with linear memory above `RUNTIME_MEMORY_BUDGET_BYTES` (64 MiB, half that limit) it disposes the runtime at once instead of lingering, and the next turn opens a fresh instance from storage. Reopening a 4 MB session took about 120 ms locally; with a 20 MiB budget every turn after the 28th reopened and all 60 completed. Session metrics count these as `runtime_retirements`.

Private `MODEL_RESPONSE_HEADERS_TIMEOUT_MS` and `MODEL_STREAM_IDLE_TIMEOUT_MS` bound each model fetch attempt and each pending body read, including the second attempt after a 401 and error-body projection. Both default to 120000ms. The header timer ends when headers arrive; active streams have no total-duration limit. Idle time while a downstream consumer applies backpressure is not counted. A timeout aborts that transport attempt and reports a fixed safe failure through the SDK; it does not replay prior tools or establish that the provider did not accept or bill the request. Alarms remain recovery wakeups rather than wall-clock model deadlines.

Run `WORKER_TOKEN` through your secret manager's environment injection and execute `node scripts/measure-curl.mjs --provider claude --samples 6` or the Codex equivalent. Add `--executor paradigm-a --tools` to measure real remote Bash, workspace edits, Code Mode store/load, concurrent tool calls, and brain callbacks. Credentials enter curl through stdin configuration and never command arguments. TTFT starts immediately before spawning curl and ends at the first nonempty assistant text delta; HTTP headers and keepalives do not count. Tool workflows may emit their first text before or after tools, so compare completion and event timings as well. Measurements retain only synthetic workflow timing, success flags, event types, and safe counters in ignored `output/`.

Add `--reasoning` for the fixed arithmetic prompt and use `node scripts/summarize-timing.mjs output/<report>.json` to inspect the breakdown. Request results retain observed admission, runtime-open, execution and checkpoint timings. Session metrics expose the resident runtime after completion, aggregate host/WASM/bridge timings and the most recent 64 model dispatches, using the existing diagnostic retention policy. Each dispatch includes a runtime ID, dispatch ID, relative start time, header and body timings, byte counts and safe private-egress diagnostics, including both attempts after a 401; a Codex socket is one entry with `transport: "websocket"` and send and frame counts. SDK display events expose elapsed model-call time; event envelopes identify their host runtime and receive time. SSE adds `streamed_at` at enqueue time, before any platform output gate or network delivery. No tracing RPCs or additional durability barriers are introduced.

Elapsed times use local clocks; never subtract monotonic timestamps from different runtimes or isolates. Production Worker clocks advance only after I/O, so synchronous WASM, parsing and copy timings can be zero despite consuming CPU. Use a local V8 CPU profile for CPU attribution and keep it separate from production network measurements. Aggregate spans overlap and include the resident SDK task tree; a host operation completing during a turn may have started earlier. Turn timing records are observational and can restart at a recovery boundary. A fresh session does not prove a cold isolate, and an enqueue timestamp does not establish when the client received text.

Run `node scripts/measure-concurrency.mjs --levels 1,4,16,32 --rounds 2` with `WORKER_TOKEN` injected through the environment for synchronized live curl bursts. Levels count sessions per provider, so the default two providers reach 64 simultaneous sessions. `--scenario tools` exercises both configured Paradigm executors; `--scenario fanout` interprets levels as requested children inside one SDK session per provider; `--scenario remote-fanout` starts those children in a remote Code Mode batch using `Promise.all`; `--scenario queue` submits that many root turns to one session per provider. Use `--providers claude` or `codex` to isolate a provider. The harness stops escalation after a failed wave and requests cancellation when a stream fails while its durable job remains unfinished. Reports contain only synthetic workflow status, timings, event metadata and safe metrics in ignored `output/`.

Concurrency measurements are closed-loop bursts, with observed client request and model-event overlap, latency percentiles and batch completion throughput. Capture runtime metrics immediately after each turn because a fast session can be evicted while waiting for a slow tail. A warm-session round reuses the conversation; `runtime_reused` identifies whether its WASM instance actually remained resident. Provider account capacity, transport tails, shared-session serialization and a shared physical execution host are separate scaling limits. These measurements do not establish sustained open-loop capacity or a global service limit.

Private egress uses service bindings with default placement and no Smart Placement, preserving the local credential boundary. Warm model credential hits avoid the account Durable Object; cold misses and rotation still consult its single refresh owner. Session preparation rewrites the background marker, stable UUID and watchdog only when admission did not already commit them unchanged. Event-to-request mappings use a bounded cache populated after a successful SQLite transaction and fall back to durable rows after eviction; event rows remain durable and reach clients only after their writes are confirmed. Checkpoint replacement reads owner, fence and revision in one local joined query before immutable writes and does not wait for confirmation itself. Placement hints cannot guarantee one colo or relocate existing objects; provider, account-broker and remote-host network paths remain separate from co-located session storage.
